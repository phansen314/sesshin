# sesshin implementation spec

How sesshin is built and tested. The [design spec](design-spec.md), [hooks spec](hooks-spec.md), [operations](operations.md), and [CLI spec](cli-spec.md) say *what* sesshin does; this document says *how*. Where they state a guarantee, this document gives the mechanism that provides it, and links back to the guarantee.

**Status: matches the code.** What is stated is decided and built.

## Toolchain

- **Go**, the version in `go.mod`'s `toolchain` line (1.26 at the time of writing). Module `github.com/phansen314/sesshin`. Linux and macOS, on amd64 and arm64 ([Supported platforms](design-spec.md#supported-platforms)). What differs by system is behind build tags; the parts that need no Mac (the [locations](#locations), the parsers of [process lookup](#process-lookup)) are tested on Linux, and the rest is cross-compiled there (`GOOS=darwin`) and run by CI's macOS job.
- **Two binaries, one module:** `cmd/sesshin` and `cmd/sesshin-hook`, built together, from the same commit, and installed side by side ([Hook cost](design-spec.md#hook-cost)).
- **`sesshin-hook` links the standard library only,** and one package besides: `golang.org/x/sys/unix`, for the macOS process table ([Process lookup](#process-lookup)), whose initialization was measured at nothing ([Hook cost](design-spec.md#hook-cost)). Go runs every linked package's `init()` at every start, whether or not the hook path reaches it, so the rule is about what is linked, not what is called ([Hook cost](design-spec.md#hook-cost) has what each library costs). A test lists `go list -deps ./cmd/sesshin-hook`, for Linux and for macOS, and fails on any package outside the standard library, `golang.org/x/sys/unix`, and sesshin's own `internal/` packages that `sesshin-hook` may import ([Import direction](#import-direction)).
- **`sesshin`'s runtime dependencies:** cobra and pflag (the CLI), `github.com/BurntSushi/toml` (`config.toml`), and, for the picker ([Restart](#restart)), `github.com/junegunn/go-shellwords` (splits `SESSHIN_PICK_OPTS` exactly as fzf splits `FZF_DEFAULT_OPTS`, comments included, which `strings.Fields` or a shell would not) and `github.com/mattn/go-runewidth` (pads the picker's columns by terminal cells, so a wide character in a `cwd` doesn't shift the rest), both the versions koan's pick uses; and `golang.org/x/sys/unix`, for the picker's raw terminal mode (`ioctl` with `Termios`, whose request numbers package `syscall` lacks on Linux) and the macOS process table. fzf itself is a runtime program, not a dependency of the module. Nothing else without a reason written here.
- **Test-only dependencies:** a JSON Schema library, for the [schema agreement tests](#schemas-in-tests); and `github.com/creack/pty` and `github.com/hinshun/vt10x`, which run a real fzf in a pseudo-terminal and render its screen for [the picker's end-to-end test](#restart); `creack/pty` also opens the pseudo-terminal of `jump`'s raw-mode test ([Jump](#jump)), on Linux and macOS.
- **Build information.** Version and commit come from Go's embedded build information (`runtime/debug.ReadBuildInfo`: the main module's version, `vcs.revision`, `vcs.modified`), as in koan's `buildinfo`, with no `-ldflags`. The version is the main module's as Go stamps it: a tag, a pseudo-version, either with `+dirty`, or `(devel)`. `install` reads `sesshin-hook`'s with `debug/buildinfo.ReadFile`, without running it, and requires the same main-module version, `vcs.revision`, and `vcs.modified` as its own ([`install`](operations.md#install) step 2). `vcs.modified` says only that there were uncommitted changes, not which, so two builds of the same commit with different uncommitted changes look the same; that matters only during development.
- **A build without VCS information** (`-buildvcs=false`, a source tree outside git, or `go install …@version` from the module cache) reports a `null` commit and `modified` false, and its version is whatever Go stamped: `(devel)` from a bare source tree, the module version from the module cache. `install` refuses a `sesshin-hook` it can't identify, one with neither a commit nor a version other than `(devel)`, since two such builds could be any two sources. A module version alone is enough: the module proxy never changes what a version names, so `go install …@version` builds can be installed.

## Package layout

Each package is created by the first task whose code needs it, never as an empty stub. The guard tests for `sesshin-hook` (its dependencies, package initialization, and [H5](hooks-spec.md#the-contract)'s `go` statements and exits) are in `cmd/sesshin-hook/guard_test.go`; they check both the shipped build and the `sesshintest` one. They check what `sesshin-hook` links **and** an explicit list of hook-path packages (`hook`, `fsys`, `jsonio`, `model`, `payload`, `proc`, `loc`, `hookconf`, `hooklog`, `record`, `statusline`, `placement`, `placement/kitty`, `live`, `testhook`, and each new one as it is created), with everything those import, so a package is held to the rules before its first verb is wired; a test fails when `sesshin-hook` links an internal package missing from the list.

### Import direction

- **`sesshin-hook` never imports** `cli`, `ops`, `config`, `settings`, `pick`, or `migrate`, nor anything that imports them. The dependency test above enforces it, because a stray import would link cobra or TOML into every hook.
- **Tier rule in code.** Nothing that writes `lifecycle.json` or `statusline.json` takes a value from `sesshin.json` ([Two tiers](design-spec.md#two-tiers)): `record` writes `sesshin.json` only through its own creation and completion steps, and `statusline` reads the sesshin ID only for rendering. Tests check both halves. For `record`: the same events run over state directories that differ only in `sesshin.json`, `state.json`, and the backend's placement leave byte-identical `lifecycle.json` files, and a source test fails when the code that builds `lifecycle.json` (`event.go`, `effects.go`, `recordLifecycle`) names `model.SesshinName`, `SesshinFile`, `ReadSesshin`, `completeSesshin`, or the placement. For `statusline`: a tick's recording is run through `fsys.Fault`, which sees every path it touches, and none may be `sesshin.json`; the file written is byte for byte the same with a `sesshin.json` present or absent.

## Locations

How the design spec's [Locations](design-spec.md#locations) are resolved: `loc.Resolve(goos, getenv)`, a pure function of the platform and the environment, called with `runtime.GOOS` and `os.Getenv`. Both platforms' paths are implemented and tested on Linux, from a table of environments.

- **`HOME` is read directly,** never through `os/user` or `/etc/passwd`. It must be absolute, even when the other variables make it unneeded, so every entry point fails the same way in the same environment. Unset, empty, or relative is a `*loc.EnvironmentError`, which `sesshin` reports as [`environment`](operations.md#error-kinds) with `variable` `HOME`, and a hook as exiting 0 silently ([Recording an event](hooks-spec.md#recording-an-event) step 1).
- **A variable is used only when absolute;** empty, unset, and relative are all ignored, and can't be told apart. The XDG variables are read on Linux only; `CLAUDE_CONFIG_DIR` on both.
- **Paths are cleaned lexically** (`filepath.Join`, so a trailing slash or `..` is folded), never resolved through symlinks, and nothing is created: the directories are made by the writes that need them.

## Mechanism

How the design spec's [Locks](design-spec.md#locks) and [Files](design-spec.md#files) are provided. The design follows koan's (`internal/fsys`, `internal/store/write.go`, and its implementation spec's Mechanism, Filesystem access and OS errors), which has been reviewed several times; where sesshin differs, the reason is given.

### One package touches the disk

`internal/fsys` is a thin interface over `os.Root` and `flock`, with a real implementation and a fault-injecting one, as koan's. Every file operation in both binaries goes through it, except a few in `sesshin`: it reads a `--input <file>` with a blocking `os.Open` and `io.ReadAll`, so process substitution and named pipes work ([Input](cli-spec.md#input)); and `install` resolves its own executable's symlinks, reads `sesshin-hook`'s build information with `debug/buildinfo`, and makes and removes the self-test's temporary `HOME` with `os` ([Install and uninstall](#install-and-uninstall)). You chose that file and can interrupt the command; no hook reads one. And `sesshin-hook`'s `main` opens `/dev/null` once at start to replace stderr ([The hook binary](#the-hook-binary)): process setup, not a file operation on sesshin's data. The fault implementation wraps the real one and, at a chosen call, returns an injected errno or ends the process: the one seam for the [OS error](#os-errors) tests, the crash tests, and the [contract tests](#contract-tests). `sesshin-hook` links it, so it follows [The hook binary](#the-hook-binary)'s rules: standard library only, no work at package initialization.

### Roots

- **One resolution per operation.** A hook or command opens the directory it works in once, with `os.OpenRoot`, locks it through the same handle (`root.Open(".")`), and makes every later call through that handle, never by resolving the path again. A write can't be split across two directories by a rename or a repointed symlink mid-operation.
- **A non-directory is `ENOTDIR`.** The path is opened with `/.` appended, so the kernel refuses a FIFO or a regular file before opening anything, as koan's.
- **The locked directory is still the session's.** Beyond koan: after locking a session directory, the hook compares the locked descriptor's device and inode (`fstat`) with the path's (`stat`). A difference means a prune renamed it aside in between: unlock, and start again once ([Recording an event](hooks-spec.md#recording-an-event) step 1).
- **Symlinks inside the state directory are followed.** Unlike koan, sesshin doesn't open the last component with `openat` and `O_NOFOLLOW`: that needs `golang.org/x/sys/unix`, which `sesshin-hook` doesn't link. The state directory is the user's own, mode `0700`, and written only by sesshin, so a symlink there isn't an input to defend against, as one in koan's user-edited tree is. `os.Root` still refuses a name that leads outside the root; that error holds no errno, and is `internal`.
- **Reads can't block, or run long.** Files are opened with `O_NONBLOCK`, and anything that is neither a regular file nor a directory (a FIFO, a socket, a device) reads as empty, so it is unusable like any malformed file; a directory fails with `EISDIR`. A file past `fsys.MaxRead` (16 MiB; sesshin's largest is a few KB) fails with `EFBIG` without being read past it, by its `fstat` size or by what was read, and is unusable too. This is what keeps a hook's time bounded ([H4](hooks-spec.md#the-contract)) whatever is in the directory.

### Locks

- **`flock` on the directory's descriptor,** `LOCK_EX`, never a lock file, as koan's write lock. `flock`, never POSIX record locks: a record lock is dropped when *any* descriptor to the file closes. The lock's `*os.File` stays referenced until unlock, so its finalizer can't close it, and with it the lock, mid-write. Go opens it close-on-exec, so the lock can't ride into `kitten`.
- **`EINTR` is retried,** around every `flock`. `flock` is reached through a package variable a test replaces to inject it, as koan's.
- **Hooks wait; prune doesn't.** koan fails at once with `busy`. A sesshin hook instead polls `LOCK_EX|LOCK_NB` until it succeeds or `hook_lock_wait_ms` runs out, on the monotonic clock, since a lost lifecycle event won't come again ([Locks](design-spec.md#locks)); the state lock is taken the same way. `prune` alone uses koan's form: one `LOCK_EX|LOCK_NB`, skipping a session that is held, and, for reservations, the state lock the same way. `spawn`, `resume`, `update`, and `migrate` poll as a hook does, for the waits design-spec [Locks](design-spec.md#locks) gives ([Spawn](#spawn)); only `update` and `migrate` take a session lock. Both are one call, `Lock(wait)`: a wait of 0 is the single try, and a lock still held at the end fails with `EAGAIN`. A hook passes each `Lock` the smaller of `hook_lock_wait_ms` and what is left of its lock deadline, taken once when the hook starts ([H4](hooks-spec.md#the-contract)), so the session lock, its one retry, and the state lock together never wait past it. The deadline is `hook.Call.Deadline`, which `Run` sets when the hook starts: a point on the monotonic clock, from `time.Now()` and not from `Env.Now`, which tests fake for timestamps. It is `hook_lock_wait_ms` times two, or `min(hook_lock_wait_ms, 1s)` for `session-end`, and the call carries it to `record` in `record.Env`, which computes each wait ([Recording an event](#recording-an-event)). Past the deadline a wait is 0, a single try; an unset deadline leaves each wait bounded by `hook_lock_wait_ms` alone.
- **The poll** retries first after 10µs, the delay doubling to a cap of 250µs, and pauses in `select(2)`, not `time.Sleep`. On Linux, a Go process with nothing else to run can't sleep less than a millisecond: the runtime waits in `epoll_wait`, whose timeout is in milliseconds, so a 50µs sleep is really 1ms. Measured on 2026-10-03 on [Hook cost](design-spec.md#hook-cost)'s machine (btrfs on LUKS, 24 cores), each event a process that opens the directory with `fsys`, locks it, reads a counter, and publishes it; lock wait in ms, pooled over interleaved repeats, no update lost and no wait timed out in any run:

  | Load | Poll | Lock wait median / mean / p99 / max | Run |
  |---|---|---:|---:|
  | Paced: 10 sessions × 4 writers × 50 events, each writer every 200ms (20 events/s per session), n=4,000 | blocking `flock`, for reference | 0.012 / 0.012 / 0.022 / 0.04 | 10.0s |
  | | **`select`, 10µs → 250µs** | 0.013 / 0.015 / 0.081 / 0.16 | 10.0s |
  | Burst: 1 session × 8 writers × 100 events back to back, n=12,000 | blocking `flock` | 0.014 / 0.051 / 0.31 / 0.67 | 0.13s |
  | | `time.Sleep`, 50µs → 1ms | 0.013 / 0.58 / 5.33 / 10.7 | 0.19s |
  | | **`select`, 10µs → 250µs** | 0.015 / 0.073 / 0.61 / 3.05 | 0.14s |
  | Saturated: 10 sessions × 4 writers × 50 events back to back, ~8,000 hooks/s, n=30,000 | `time.Sleep`, 50µs → 5ms | 0.21 / 1.79 / 22.3 / 106 | 0.26s |

  At 20 events/s per session nearly every lock is free at the first try, and every poll does the same. A burst on one session — parallel tool calls, an async `PostToolUse` racing its `Stop`, the contention the session lock exists for — is where the poll shows: a millisecond sleep makes the mean wait ten times a blocking `flock`'s, and the `select` poll comes within 50% of it. Saturated, the CPU is the bottleneck: run time and mean wait are the same for every poll (a blocking `flock` too: 1.71ms mean), and only the tail differs, widening with the cap; at 250µs it is level with `time.Sleep`'s. A 5ms cap has the worst tail, 106ms. A cap below 250µs was not measured; the burst's tail was still falling, the saturated one level. Every wait stays far inside `hook_lock_wait_ms`.

### Writing files

- **Temp files** are named `.sesshin-tmp-<random>`: hidden from reads, recognizably sesshin's, and the same prefix for a directory renamed aside, so a leftover is found by its prefix and judged by its age ([Files](design-spec.md#files)). Each is created exclusively (`O_CREATE|O_EXCL`) through the root, mode `0600`, not koan's `0644`, since sesshin's files hold paths and costs. Files are set to `0600` with `fchmod` after the create, since the umask can take bits from `open`'s mode but not from `fchmod`'s; directories get `0700` less the umask. The random part is 12 bytes from `math/rand/v2`, seeded by the runtime, not koan's `crypto/rand`: the name needs to be unique, not secret, and `O_EXCL` catches a collision. Linking `crypto/rand` (which brings the FIPS 140 module's packages) measurably slows every start. Measured on 2026-10-03, n=1000 interleaved, warm, three runs agreeing within 10µs; the median start-to-exit of a binary that does nothing was 0.951ms, the same with `math/rand/v2` linked 0.953ms, with `crypto/rand` 0.977ms; `sesshin-hook` linking `fsys` was 0.986ms with `math/rand/v2` and 0.999ms with `crypto/rand`.
- **Publishing,** as koan's `Publish`: write the temp file in full and close it, then `rename` it over the destination. A failure before publishing removes the temp file and returns the OS error, with nothing published. Once published, failing to flush the directory is not an error.
- **A two-step write for the statusline.** The temp file is written, then committed (renamed) or aborted (removed) by the caller, because the statusline renames only if the stored `received_ns` isn't newer ([`statusline`](hooks-spec.md#statusline) step 6). `Publish` is the one-step form everyone else uses.
- **No flush, but one.** koan flushes every write; sesshin flushes only `state.json`: the file before publishing, then its directory ([Files](design-spec.md#files): a flush is 90% of a write's cost).
- **Removal by renaming aside.** `prune` renames a session directory to a `.sesshin-tmp-` name in `sessions/`, then removes it with `RemoveAll` through the root, as koan's `delete-folder`.
- **Directories are created** mode `0700`, only by the writes that need them ([Recording an event](hooks-spec.md#recording-an-event) step 1).

### Log rotation

[Log](hooks-spec.md#log). Appends take no lock. A hook that finds `hooks.log` past 1 MiB on its own descriptor takes `flock(LOCK_EX|LOCK_NB)` on that descriptor, and skips rotation if it is held: another hook is rotating. Under it, the hook checks again that the path names the same file (`stat` against `fstat`) and that it is still past the limit, then renames it to `hooks.log.1`. A hook that noticed at the same time gets the lock only after the rename, finds the path naming another file, and skips. Nothing waits: the lock is a single try, released when the hook closes its descriptor.

- **Opening:** `fsys.Root.OpenAppend`, `O_WRONLY|O_APPEND|O_NONBLOCK` without `O_CREATE` first; only on `ENOENT` is the file created, exclusively, and set to `0600` with `fchmod`, as temp files are; losing that race opens the other creator's file, for at most three rounds, then the last error is returned, since rotation can keep moving the file. A FIFO in its place fails the open with `ENXIO` when no one reads it, and a write with `EAGAIN` when its reader never reads: the write is one raw `write(2)`, because `os.File.Write` on a non-blocking descriptor waits in Go's poller.
- **Lines:** the timestamp is now, as a [timestamp](design-spec.md#timestamps). The message is cut at 2,048 bytes, at a character boundary, ending in `…`. Every field is escaped onto one line: `\n`, `\r`, `\t`, `\\`, `\xNN` for the rest of C0 and DEL, and `\uNNNN` for C1 (NEL among them), U+2028, and U+2029, which some viewers break lines at; in the verb and session, a space is `\x20` too, so a line splits into its four parts at its first three spaces. An empty verb or session is written `-`. Invalid UTF-8 is written as is.
- **Errors** are returned to the caller, which ignores them: a hook has nowhere else to report them. A test runs sixteen writers through rotation at a 4 KiB limit, checks that every line is whole, and that `hooks.log.1` is always past the limit; it fails when the same-file check is removed.

### OS errors

As koan's OS errors:

- **Names.** The `io` error kind's `code` is the symbolic errno (`ENOSPC`), never a number, the same on Linux and macOS. The standard library has no errno-to-name function, so there is one table per OS, written with `syscall` constants. Aliases get one name everywhere (`EAGAIN`, `ENOTSUP`, `EDEADLK`). A completeness test fails for any errno from 1 to 255 with a real message and no name. An errno not in the table is `internal`, never an invented name. Unlike koan's map, the table is a `switch` in a function, so `sesshin-hook` does no work at initialization.
- **Extraction** with `errors.As` through `*os.PathError`, `*os.LinkError` and `*os.SyscallError`; an error with no errno is `internal`.
- **Meaning is decided where the call is made.** Each call site classifies its own errnos (for example, `ENOENT` opening a session directory a hook can't adopt is "nothing to record"; `EAGAIN` from prune's try-lock is "skip this session"), and only what no call site claims falls through to `io` in a command, or to a log line in a hook.

## JSON reading

Three kinds of JSON, read three ways. None of them uses `json.Unmarshal` on input sesshin didn't write: it validates the whole input before decoding anything, so one syntax error yields no fields, it matches keys case-insensitively, and a repeated key silently takes the last value.

- **Hook payloads: streamed into a struct, read only.** One tolerant decoder on the standard library's token stream (`json.Decoder` with `UseNumber()`, read with `Token()`) fills the payload struct directly: every field optional, a wrong type is an absent field, the rest still decode ([Reading the payload](hooks-spec.md#reading-the-payload)). Members read before a syntax error are kept, and after the closing brace the decoder reads one token more, so that anything but whitespace there is reported in `Err` (`trailing data after the payload`) and logged like any other fault, as the hooks spec records and renders whatever decoded ([`session-start`](hooks-spec.md#session-start), [`statusline`](hooks-spec.md#statusline)). Values sesshin doesn't read (a large `tool_response`, say) are skipped without being built: decoded into a no-op `json.Unmarshaler`, which checks their syntax and copies nothing. No hook builds a tree. Keys match exactly, and a repeated key takes its last value, even one of the wrong type, as a map would: Claude Code doesn't repeat keys, so this only keeps the rule simple. Nothing about a payload is an error but empty stdin and a `session_id` that isn't a UUID. A fuzz test checks the decoder against `json.Unmarshal` into a map, for every input both read whole, with only whitespace after the object. Measured 2026-10-03 (`internal/payload/bench_test.go`, warm, medians of 6): the captured 2.1 KB statusline payload in 22.6µs (527 allocations, about one per token, since the token stream boxes each); `post-tool-use` payloads of 1 KB, 50 KB, and 1 MB, almost all a `Read`'s file content, in 8.0µs, 230µs, and 5.0ms. A skipped value is scanned twice, once to find its end and once to check it, so large payloads cost about 5ms per MB. Skipping by walking `Token()` instead, which builds every skipped string, was 21% faster at 1 MB and 11% at 50 KB, but 24% slower at 1 KB and 17% on the statusline's; the difference is about 25µs either way, beside a hook's ~1.25ms.
- **The statusline payload is stored as raw bytes,** not re-encoded from a tree: a `json.RawMessage` in the `statusline.json` struct, which the encoder re-indents with its key order, number text, and escapes as received ([File format](design-spec.md#file-format)). Before storing, one pass escapes raw U+2028 and U+2029, which the encoder leaves alone inside a `RawMessage` (though it escapes them in strings it encodes itself), and another rewrites each lone-surrogate escape to `\ufffd`, in place (both are six bytes), since the strict reader refuses them ([File format](design-spec.md#file-format)). A payload that isn't valid UTF-8, is nested deeper than `jsonio.PayloadDepth` (64), or repeats a key in any object after the rewrites (two lone surrogates become the same `\ufffd`, and a stored file with a repeated key would read as unusable), is unparseable for the write: rendered from what decoded, not stored. The cap is for size, not the encoder's limit: indented output grows with the square of the depth, so a 20 KB payload nested 9,995 levels would be about 200 MB on disk. A fuzz test checks that whatever `Payload` returns, written into a file, reads back through the strict reader with no repeated key. The decoder replaces invalid UTF-8 in the strings it decodes with U+FFFD, so rendering still works.
- **sesshin's own files are read strictly,** against their validators ([Validation](#validation)); anything else makes the file unusable. **Tree, then validate, then convert:** the file is read into the ordered tree (the strict reader), and the validator checks the tree, copying each value into the file's struct as it passes. The struct is returned only when every check passed, so the copy itself never fails. The checks need what a struct decode loses: a missing key versus `null`, unknown and repeated keys, and a number's literal text. Measured 2026-10-03 on realistic files (a captured 2 KB payload with `prompt_cache`): warm, 12µs for an 872-byte `lifecycle.json` and 35µs for a 2.8 KB `statusline.json`; in a fresh process, n=600 interleaved, medians +0.055ms and +0.092ms over a do-nothing run, +0.138ms for both, which the statusline reads on every tick. `json.Unmarshal` was about twice as fast warm, but can't see repeats and matches keys case-insensitively. Validation on top of the parse, measured 2026-10-03 (`internal/model/bench_test.go`, warm, medians of 6, on fixtures of 866 and 2,462 bytes): `lifecycle.json` 13.8µs parsed, 15.9µs read and validated, so +2.1µs (38 allocations, mostly the nullable fields' pointers); `statusline.json` 37.7µs and 38.3µs, +0.6µs, since its payload is checked only for being an object.
- **Operation input (`--input`) is read as strictly,** by the same mechanism as sesshin's own files: `ops.DecodeInput` reads the ordered tree, reports a read failure at `""` and each repeated key at its pointer, then runs the operation's own checks over the members, any member they don't ask for being unknown; `ops.CheckInput` does the last step for input built from flags. Every problem is collected into one `invalid-input`. Its input schemas have `additionalProperties: false`, and `Unmarshal` would bind `DRY_RUN` to `dry_run` and keep the last of a repeated key, so neither would reach the schema check ([Input](cli-spec.md#input)).
- **The ordered tree,** as koan's: `jsonio.ParseValue` builds objects as ordered member lists and numbers as `json.Number`, from the same token stream. It reads every sesshin file, `settings.json`, and kitty's `ls` output. For `settings.json`, it lets an edit keep the user's key order and number text ([Registration](hooks-spec.md#registration)); only `sesshin` reads that file. The read is strict: invalid UTF-8, a byte-order mark, a syntax error, trailing data, or a lone surrogate escape (which the decoder would silently turn into U+FFFD) is `corrupt` ([Errors](operations.md#errors)): `install` and `uninstall` fail rather than propose an edit of a file they misread.
- **The tree's nesting is limited to 9,990 levels,** as koan's. The builder is iterative, but the ordered type's `MarshalJSON` recurses, so a deeper value would end in Go's fatal stack overflow, and the encoder rejects output past 10,000 levels anyway.
- **`settings.json` has its own limit of 64 levels** (`settings.MaxDepth`). A user's file is a few levels deep. The proposal is indented and grows with the square of the depth, so a deeper file is `corrupt`. The limit is the same number as `jsonio.PayloadDepth`, but not tied to it.

## JSON writing

The standard `json.Encoder` with `SetEscapeHTML(false)` and two-space indent, so its output is the design spec's [File format](design-spec.md#file-format): key order from struct field order, which follows each schema; the statusline payload as stored raw (see [JSON reading](#json-reading)); the ordered tree in its stored order with its numbers' original text. With HTML escaping off, the encoder escapes exactly `"`, `\`, U+0000–U+001F, U+2028, and U+2029 in the strings it encodes, and replaces invalid UTF-8 with U+FFFD.

- **Strings inside the ordered type** are written by an encoder that also has `SetEscapeHTML(false)`. One written by `json.Marshal` would carry `\u003c` for `<`, which the outer encoder doesn't undo.
- **No nil collections.** nil encodes as `null` where the File format and the schemas want `[]` or `{}` (`user_vars`, `changes`, `pruned`, `warnings`). The one write function every file goes through replaces nil slices and maps with empty ones before encoding, so no caller can forget.

A test pins the exact bytes of each file kind, including raw `<>&` and non-ASCII, an escaped U+2028 (in sesshin's own strings and in a stored payload), a payload's numbers and escapes as received, and empty collections.

## Validation

- **At runtime, hand-written validators** in `internal/model`, one per file schema (`ReadState`, `ReadLifecycle`, `ReadStatusline`, `ReadSesshin`, `ReadReservation`, `ReadInstall`). They are used by every read, and by `install`'s self-test ([`install`](operations.md#install) step 2). Neither binary links a JSON Schema validator. The schemas' patterns are hand-written too, since `sesshin-hook` can't compile a regexp at initialization; a test and a fuzz target check each against its pattern compiled by `regexp` (all but `^/`, which is `absolute`'s prefix test, covered by the agreement tests).
- **Order:** a read failure, then `schema`, which must be the integer literal of the supported version, then repeated keys, then every field in schema order. Any failure makes the file unusable, treated as missing ([Format versions](design-spec.md#format-versions)). A `schema` that is an integer literal (within ±(2^53 − 1)) but another version makes it **in another format**, `FileResult.OtherFormat`, with the version found in `FileResult.Found` (and a reason such as `in format 1, not 2`), which writers leave alone; every other failure makes it corrupt, and the next write replaces it. A repeated `schema` key is corrupt, with no version check, since its version is ambiguous (as koan's). A failure at the first two stops there; after that every problem is collected, for the log.
- **Open sets are checked for shape, never value** ([Open sets](design-spec.md#open-sets)).
- **Rules beyond the schemas,** stated only in the design spec's prose, are checked too, and make a file unusable like any other failure: `lifecycle.json`'s `session_id` is its directory's name; `pid_started_at` is `null` exactly when `pid` is, in `lifecycle.json` and `statusline.json`; a reservation's `job` is its file name's key and its `token` the name's token ([Reservations](design-spec.md#reservations)); an `extra` is within its [limits](design-spec.md#user-owned-extra); `end_reason` is `null` while `ended_at` is (the reverse doesn't hold: a reason that fails its guard leaves `ended_at` set with `end_reason` `null`); every timestamp is a real time (no `02-30`, no hour `24`), so its conversion can't fail. A rule is checked only between fields that passed their own checks. Not checked, on purpose: time order between timestamps (`started_at` ≤ `last_start_at` ≤ `last_event_at`, `cost_sample.at` ≤ `received_at`), since a clock stepped back makes sesshin's own writes break it, and a corrupt `lifecycle.json` is replaced from scratch; and rules on an open set's value (`stall_reason` only while `waiting`), per Open sets.
- **The `schema` field** of each file struct has a type of its own that always encodes as the file's version, so no writer can leave it unset.

### Schemas in tests

As in koan: a generator (`go generate ./internal/tools/schemagen`) extracts every JSON block with an `$id` from the specs into `schemas/`, a test fails if the extraction is stale, and agreement tests run a corpus of valid files, each mutated one field at a time, through both the validators and the schema library. Both must accept, or both reject at exactly the same fields. Problems from the rules beyond the schemas, and repeated keys, which the library can't see, are marked by the validator and left out of the comparison; each has its own tests. Every operation's input decoder is checked the same way, over the mutations of one valid input, and each accepts what its `<op>-input` schema accepts and nothing else, but for the stated rules beyond it (`list`'s `fields` names, an argument's NUL). Every envelope the in-process tests produce (`internal/ops`, `internal/cli`) is also validated against `envelope`, its operation's output schema, `error`, `warning`, and, for usage errors, `usage-details`. The output schemas are open in the specs ([Conventions](operations.md#conventions)), so `schematest` compiles them closed: every object schema in an output schema (`envelope`, `error`, `warning`, `session-ref`, `session-view`, `session-projection`, `usage-details`, and each `-output`) that lists `properties` and says nothing of others gets `additionalProperties: false`, and output the spec doesn't describe still fails a test. An object marked `"additionalProperties": true` stays open there too: for a shape another program owns. An `allOf` member, a `then`, or an `else` refines the object around it, so it isn't closed itself, though what it nests is, and an `if` is left alone: that is how `error` and `warning` give each kind's `details`. An [open set](design-spec.md#open-sets)'s `examples`, the values this release writes, become its `enum`, so a value the spec doesn't list fails too. A test fails if a generated output schema closes an object, or has an `enum` other than `liveness`'s. The pickers' output leaves each action's `input` open, so the picker tests check it against its operation's `-input` schema, and a successful action's result against its `-output`.

**Integer literals.** Every integer-typed field in sesshin's own files accepts only integer literals (`2`, not `2.0` or `2e0`), as koan's. The two non-integer numbers, `statusline.json`'s `burn_usd_per_hour` and `cost_sample.usd`, accept any JSON number at least 0 that a `float64` holds: one past its range (`1e400`) is a rule beyond the schema, and a negative one too small for a `float64` (`-1e-400`, which parses as `-0`) is caught from its text. The stored `payload` is not checked field by field, nor are the numbers inside `sesshin.json`'s `extra`, which keep any JSON number's text, as koan's `extra` does (`1e400` included): `extra` is checked for being an object within its [limits](design-spec.md#user-owned-extra), its byte size measured as `MarshalLine` would write it. JSON Schema's `integer` accepts any integral value, so the agreement tests leave non-integer literals out of the comparison, and test them separately. A test fails if a schema allows a non-integer number anywhere but those two fields, `payload`, and `extra`.

**Library:** `github.com/santhosh-tekuri/jsonschema/v6`, as koan's, imported only by a test-helper package. It supports draft 2020-12 with `$ref` by `$id`, validates `json.Number` without converting it to `float64` (as a `float64`, `9007199254740993` rounds to a value that passes `event_seq`'s maximum), reports each error with its JSON Pointer, and loads schemas from local files under a fixed base URI. Its regex engine is replaced by Go's `regexp`, after rewriting each `\uXXXX` escape to `\x{XXXX}`: the one ECMA-262 syntax the specs' patterns use that RE2 lacks (the text pattern's `[^\u0000-\u001F\u007F-\u009F\u2028\u2029]`). Syntax both engines accept with different meanings (`.` outside a class, `\s`, `\S`) is refused, so a pattern using it fails to compile. One lookahead is understood: a flat negative one at the start of a pattern (`^(?!X)Y`, as `defs`' `job` has), checked as two patterns, matching `Y` and not `X`; any other lookahead is refused. Checked 2026-10-04: the specs' patterns need nothing else.

## Settings

- **`hooks.properties`** ([Hook settings](design-spec.md#hook-settings)), `internal/hookconf`: read whole with one `fsys.FS.ReadFile`; a missing file (or config directory) is the default, without a log line. Parsed by hand: it is one key. The value is decimal digits only (no sign, no spaces), so `strconv.Atoi`'s `+5` is refused. Every problem is collected, each naming its line, and a file with any problem is wholly the default. `Read` returns the default alongside its error, so a hook takes the settings and drops the error; `install` maps a `*hookconf.CorruptError` to `corrupt`, and classifies any other error as every call site does ([OS errors](#os-errors)): `io` with its errno, else `internal`.
- **`config.toml`** ([`config.toml`](design-spec.md#configtoml)), `internal/config`: BurntSushi's decoder (v1.6.0) into pointer fields, so an absent key keeps its default. A syntax or type error (`30.0` and `"30"` are both type errors) stops the decoder at the first, and is reported alone; otherwise every key the decoder doesn't place (`MetaData.Undecoded`, which names a table and each key in it) is unknown, and every negative value is out of range, all in one `detail`. TOML's other integer forms (`1_000`, `0x10`) are integers, and accepted. A `*config.CorruptError` maps to `corrupt`; any other read error is classified as every call site does: `io` with its errno, else `internal`.
- **Durations saturate.** Every `config.toml` setting is unbounded above, and `time.Duration` overflows past about 292 years: a negative duration would put `prune`'s cutoff in the future and remove every ended session. Hours are capped at the largest `time.Duration` before conversion (`RetainHeadless`). Days go through `config.DaysBefore`, which caps them at 1,000,000 (about 2,700 years) before `time.Time.AddDate`: `AddDate`'s arithmetic wraps long before `math.MaxInt64` (measured: `math.MaxInt64` days back lands on the next day). A test runs `math.MaxInt64` through each setting and through `prune`'s `retain_days`.

## The hook binary

How the [hooks contract](hooks-spec.md#the-contract) is provided.

- **H1, H2:** `main` defers a `recover` before it touches argv, stdin, or any file, and returns normally after a panic, so the process exits 0. Nothing `sesshin-hook` links calls `os.Exit`: `main` returns, and the process exits 0. When the verb is `statusline`, the recover also prints the fallback line ([Rendering](hooks-spec.md#rendering)): a panic that reaches it never entered the statusline's own frame, so no line has been printed. It reads argv only after the panic, and writes a constant, which can't panic again.
- **Nothing runs before the recover.** Package initialization runs before `main` and can't be recovered, so the packages `sesshin-hook` links have no `init()` and no package-level variable whose initializer does work or can panic: a guard's regexp is compiled lazily, inside the recovered path, or the guard is hand-written. A test parses every package of sesshin's own that `sesshin-hook` links and fails on a `func init` or a package-level initializer that calls anything (conversions included), asserts a type, builds a map (`runtime.makemap`), receives from a channel, divides, indexes, or slices; function literals are exempt, since their bodies don't run at initialization. Another fails on `os.Exit`, `log.Fatal*`, or `log.Panic*` in any of them. `golang.org/x/sys/unix` is outside both: its package-level variables are initialized by a few assignments and an allocation, measured at nothing ([Hook cost](design-spec.md#hook-cost)), and it never exits.
- **SIGPIPE.** Right after the recover, `main` calls `signal.Ignore(syscall.SIGPIPE)`, so a write to a stdout Claude has closed returns `EPIPE` instead of killing the process with exit 141. The statusline ignores that error.
- **What can't be recovered.** A fatal runtime error (out of memory, a stack overflow) bypasses `recover`, and by default exits 2: the blocking code. So, right after the recover, `main` calls `debug.SetTraceback("crash")`, which ends a fatal error by SIGABRT (exit 134) instead, a non-blocking error to Claude Code, and sets `RLIMIT_CORE` to 0, so the abort writes no core file. (A `core_pattern` that pipes to a handler, such as Ubuntu's apport or systemd-coredump, ignores that limit, so the handler may still collect one.)
- **H3:** nothing writes to `os.Stdout` or `os.Stderr` but the statusline's single final `Write` of its buffer. The `statusline` verb has its own outer recover, around decoding the payload as well as the steps, and prints the fallback line ([Rendering](hooks-spec.md#rendering)) when the buffer hasn't been written. **stderr is `/dev/null`.** After the steps above, `main` replaces file descriptor 2 with `/dev/null` (opened write-only, without close-on-exec, since with stderr closed the open lands on 2 itself and `kitten` must inherit it), so a stray write from the runtime or a library can never reach Claude. If that fails, the hook carries on. The cost: a crash's stack trace goes nowhere, so crashes are debugged with the `sesshintest` build or by running the hook by hand; the SIGABRT exit status still reaches Claude Code.
- **H4:** the bounded lock wait above; `terminal-sync`'s `kitten @ ls` runs through `exec.CommandContext` with a 1-second deadline and `cmd.WaitDelay` of 100ms. Without it, `Wait` waits for every holder of the output pipe, so a grandchild of `kitten` could stretch the wait past the bound.
- **H5:** no `go` statement in sesshin's own code; a test parses every non-test file in the module for one.

## Process lookup

`internal/proc`, from [Liveness](design-spec.md#liveness) and the [verified](design-spec.md#claude-code-21288) fact that `CLAUDE_PID` is the hook's direct parent. It never starts a process and takes no lock. The rules below (which `CLAUDE_PID` to take, the walk, `nested`'s fallback, what no such process is) are one implementation over a process table; only the table reader differs by system. On Linux it reads `/proc` through `fsys` (`ReadFile`, and `Readlink` for `exe`). On macOS it reads `sysctl` through `golang.org/x/sys/unix`'s libc-backed helpers, without cgo: `SysctlKinfoProc("kern.proc.pid", pid)` for a process's `kinfo_proc`, `SysctlRaw("kern.procargs2", pid)` for its arguments and initial environment, and `Sysctl("kern.bootsessionuuid")` for the boot. On other systems it finds nothing.

- **`CLAUDE_PID`** is accepted when it is decimal digits naming the hook's parent or its parent's parent, read from the table's ppid: `/proc/<pid>/stat`'s ppid field on Linux, `kinfo_proc`'s `e_ppid` on macOS. A further ancestor's is inherited from an outer session, so the walk runs instead.
- **The walk** starts at the hook's parent and stops at the first `claude`. On Linux, that is a process whose `stat` name is `claude`, or whose `/proc/<pid>/exe` is `<…>/claude/versions/<version>` (a name starting with a digit), with the kernel's ` (deleted)` suffix ignored, since the updater replaces the binary under a running Claude. On macOS, it is a process whose `p_comm` is `claude`, or whose executable path (`KERN_PROCARGS2`'s first string, the path it was started by) is `<…>/claude` or `<…>/claude/versions/<version>` (a name starting with a digit). On both, it stops with nothing at pid 1, at a process it can't read, and after 256 steps, since the table is read while it changes and a cycle must not hang a blocking hook.
- **`pid_started_at`** is the start time, prefixed by the system and the boot. On Linux it is `linux:<boot_id>:<starttime>`: `/proc/sys/kernel/random/boot_id`, which must be a lowercase UUID, and `/proc/<pid>/stat` field 22, read after the last `)` since the command name can contain spaces and parentheses. On macOS it is `darwin:<boot session>:<sec>.<usec>`: `kern.bootsessionuuid` lowercased, which must then be a UUID, and `kinfo_proc`'s `p_starttime`, its seconds in decimal and its microseconds as six digits. When either part can't be read, nothing is found: `pid` is `null` exactly when `pid_started_at` is.
- **`nested`** is `CLAUDECODE` set, to any value, in Claude's initial environment: `/proc/<pid>/environ` (NUL-separated) on Linux; on macOS, the environment in `KERN_PROCARGS2`, whose layout is a 32-bit `argc` (in the machine's byte order), the executable path, NUL padding, `argc` argument strings, then environment strings until an empty one (what follows is Apple's own strings, not the environment). A buffer that doesn't parse to that layout can't be read. When the environment can't be read, `nested` is whether the walk finds another `claude` above Claude, and `null` when that walk stops on a process it can't read.
- **No such process,** for [`StartedAt`](#liveness), is `ErrNoProcess`: on Linux, the process's `stat` missing (`ENOENT`) or vanishing as it is read (`ESRCH`); on macOS, `ESRCH`, or `kern.proc.pid` answering with no entry, which the kernel does for a pid that doesn't exist and `SysctlKinfoProc` reports as `EIO`. Any other error is the check failing, which a reader takes as [unknown](design-spec.md#liveness).
- **Cost:** measured 2026-10-03 on Linux (`BenchmarkFind`, warm, n=6), about 49µs by `CLAUDE_PID`: four small reads (the hook's `stat`, Claude's `stat`, `boot_id`, Claude's `environ`). On macOS the same lookup is four `sysctl` calls (two `kern.proc.pid`, `kern.bootsessionuuid`, `kern.procargs2`); not yet measured.
- **Tests** run on a fake `/proc` tree for each rule, and on the real table on Linux and macOS: the test binary, copied to `claude` and to `claude/versions/9.9.9`, and run by a link named `claude` to a versioned copy, runs itself as a child that looks it up as a hook would. The macOS readers' parsing (`KERN_PROCARGS2`'s layout, the fields taken from `kinfo_proc`, the boot session, the errors) is pure and built on every system, so it is tested on Linux from byte fixtures, and the shared rules run over a fake `sysctl` table there too; only the calls into `sysctl` themselves need a Mac, and CI's macOS job runs them.

## Liveness

`internal/live`, from [Liveness](design-spec.md#liveness). A hook-path package since the Adopt rules ([Recording an event](#recording-an-event)): `sesshin-hook` links it, so it follows [The hook binary](#the-hook-binary)'s rules. It reads no files: every operation that reads sessions reads each session directory (through `ops.readSessionFiles`, see [List and show](#list-and-show)), and `record` reads them for Adopt rule 3, and each passes what it read.

- **API.** `Derive(sessions, now, startedAt)` judges all sessions together, since rule 3 compares them, and returns one `Result` per session, in order: the state (`Live`, `Ended`, `Unknown`), the end reason (the stored `end_reason`, `superseded`, or `""`), and last seen. A `Session` is its directory name and its `lifecycle.json` and `statusline.json`, each `nil` when missing or unusable. The TTL is the constant `UnknownPIDTTL`; `live` reads no config.
- **`startedAt`** is `proc.StartedAt` over `fsys.OS` in production and a fake in tests. `Derive` calls it once per distinct pid.
- **No such process** is `proc.ErrNoProcess`, which `proc.StartedAt` returns when the process's `stat` is missing (`ENOENT`) or vanished as it was read (`ESRCH`). That, or a different start time, is ended. Any other error is unknown: a missing `boot_id` fails with `ENOENT` too, so the errno alone can't say the process is gone.
- **Order of rules:** an unusable `lifecycle.json` is unknown; `ended_at` set is ended; then the pid pair (lifecycle's, else a usable statusline's) is checked, or the no-pid limit (`UnknownPIDTTL`, a constant 24 hours) applies when there is none; last, rule 3 ends all but the top-ranked live session of each pair as `superseded`.
- **Tests** are in-process, on a fake process table, plus one on the real `proc.StartedAt` for the test's own process.

## Recording an event

`internal/record`, from [Recording an event](hooks-spec.md#recording-an-event), [Creating `sesshin.json`](hooks-spec.md#creating-sesshinjson), and [Sesshin IDs](design-spec.md#sesshin-ids). It is a hook-path package (see [The hook binary](#the-hook-binary)): standard library and sesshin's own hook-path packages, no `init`, no `go` statement. It is the only code that writes `lifecycle.json` for an event, and the only code that issues sesshin IDs.

- **API.** `record.Record(env, event) error`. A verb maps its payload to an `Event` (`record.FromPayload(kind, payload)` copies everything the payload carries; the verb sets `Claude`, where it has looked up the process) and calls `Record` with `Call.RecordEnv()`, which always sets the placement of the backend the environment names. The error says why nothing was recorded and has already been logged; the verb ignores it. `record.ErrNothingToRecord` is the one not logged: a hook that can't adopt, finding no session directory or no `lifecycle.json`. A `lifecycle.json` that is unusable (for a hook that can't adopt) or can't be read (for every hook) is logged, and nothing is written. `Record` takes the session lock through `Env.withLocked`, as `SetCwd` and `SetPlacementSync` do.
- **`record.SetCwd(env, cwd) error`** is `cwd-changed`'s entry point: not an event, so it moves no clock. It scrubs `cwd`, and returns at once, with no lock, when that leaves it empty. Otherwise it takes step 1 as `Record` does (`lockSession`, with its retry after a prune), but never adopts and never creates the directory, so a missing directory or `lifecycle.json` is `ErrNothingToRecord`. It reads `lifecycle.json`, and writes it with only `cwd` changed, unless `cwd` is already stored. An unusable or unreadable file is logged and left as it is: `SetCwd` replaces nothing. The lock step is `Env.withLocked(adopt, f)`: lock, run `f` on the session's root, unlock, logging a failed lock; `terminal-sync` writes `sesshin.json` through it.
- **`record.SetPlacementSync(env, apply) error`** is `terminal-sync`'s write, after `kitten` has returned. It takes the lock through `withLocked(false, …)`, so it never adopts and never creates the directory: a missing directory or `sesshin.json` is `ErrNothingToRecord`. It reads `sesshin.json`; an unusable or unreadable one is logged and left as it is, and a `null` placement writes nothing, without calling `apply`. Otherwise it calls `apply(old)`, which returns the placement to store and whether it changed, and writes `sesshin.json` with only the placement replaced when it did. The hook's `apply` returns `old` unchanged unless `kitty.Parse(old)` names the environment's socket and window, then returns `kitty.Apply(old, synced)`. `apply` runs under the lock, so it starts no process.
- **`Event` is a `Kind` and its qualifiers.** A `Kind` is a row of the [effects table](hooks-spec.md#effects-table): `SessionStart`, `UserPromptSubmit`, `PostToolUse`, `PostToolUseFailure`, `Stop`, `StopFailure`, `PermissionPrompt`, `ElicitationDialog`, `ElicitationComplete`, `PreCompact`, `PostCompact`, `SessionEnd`. The guard column, whether the hook may adopt (every kind but `SessionEnd`), and whether placement is replaced (`SessionStart`) follow from the kind, in `record`, so no verb sets them. The qualifiers are the payload's values: `PromptID`, `PermissionMode`, `Source`, `Trigger`, `Reason`, `Error`, the two counts, `SessionTitle`, and for a start or an adoption `Cwd`, `TranscriptPath`, `Model`. `Record` guards and scrubs them again, so a value that fails costs its qualifier or field, never the write. `Claude` is `session-start`'s lookup, made before any lock; with none, a file being created looks Claude up itself, through `Env.Lookup` (`proc.Find` when nil).
- **`Env`** is what the pipeline needs of the call: the `fsys.FS`, the locations, the session ID, the event's time (`Now`), `LockWait`, `Deadline`, `Getenv`, `Log`, `Lookup` (`proc.Find` when nil), and `Placement`. `Getenv` and `Log` have no nil guards: every caller sets them. `Placement(old)` is the terminal backend's (the kitty backend): it takes the placement `sesshin.json` has and returns the one to record. `record` never calls it for a session that `lifecycle.json` says is nested, or under `TMUX` or `STY`, and records `null`; with no backend it is nil.
- **Steps 1 to 6** are `lockSession`, `recordLifecycle` (steps 2 to 4), and `completeSesshin` (step 5), under the one session lock. Step 1 opens the session directory once with `FS.OpenRoot(<state>/sessions/<uuid>)` (`loc.SessionDir`), creating it with `fsys.OpenRootCreate` (`MkdirAll`, mode 0700, parents included, after an open that failed with `ENOENT`) only for a hook that can adopt. The state lock is the lock on `sessions/`, opened when an ID is to be issued; `state.json` is written through a root on `<state>`.
- **Reading and writing a file** are one helper each, in `read.go`: `readFile` reads a file of the session or state directory and ends as missing, unreadable, unusable, or usable, logging the unreadable and unusable cases in the log's grammar ([Log](hooks-spec.md#log)); `write` marshals and publishes, logging a failure, a marshaling one included. The file names are constants in `model` (`model.LifecycleName`, `SesshinName`, `StatuslineName`, `StateName`), beside their readers, and `loc` builds the session paths (`SessionsDir`, `SessionDir`).
- **The backend interface** is `placement.Backend`: `Tag()`, `Recognize(getenv)` (the placement, or nil), `Replace(next, old, resumed)`, `Valid(p) bool`, `Address(p)` (the minimal placement that addresses p's window, for the output of `send` and `focus`; canonical, so `spawn` compares two by their bytes), and `Stored(p)` (title and user variables, for the pickers and `resume`). Each optional ability is an interface of its own, found by type assertion: `Syncer`, `Launcher` (with `UserVars() bool`), `WindowChecker`, `Locator` (find a window by pid; a nil error always comes with a placement, and `send` and `focus` treat a nil one as nothing found), `Sender`, `Focuser`, and `Hinter`, what the environment must hold for the backend to place the caller, which the `unavailable` message lists. `placement.Detect(list, getenv)` applies `Multiplexed`, then asks the list in order, and returns the backend and the placement it recognized; `record` applies the nested rule, since only it knows `nested`. `placement.For(list, tag)` finds a stored placement's backend, or nil, and `placement.Of(list, p)` does so by the placement's `terminal`. The list is `backends.All()` in `internal/placement/backends`, a new slice on each call so no caller can change another's, and a package of its own because `kitty` imports `placement` (for `LaunchSpec`, `Var`, `LaunchError`, `SendError`, and `Existence`, which are `placement`'s, not a backend's) and `placement` therefore cannot import `kitty`; it is a composite literal, never filled by `init` (`sesshin-hook`'s guard tests forbid package initialization that does work). `ops` takes the list as `ReadEnv.Backends` (real: `backends.All()`; tests: `placementtest.Kitty`, or a backend with fewer abilities). The interface is opaque: everything outside a backend holds a window as a placement (`*jsonio.Object`) that the backend has validated, and reads none of its keys but `terminal`. The abilities are `Syncer.Sync(p) (Update, error)` (p is the recognized placement; the `Update` applies what it learned to a stored placement), `Launcher.Launch(LaunchSpec) (*jsonio.Object, error)` (the launched window's placement; `LaunchSpec.Caller` is the caller's placement from `Detect`, which ops passes untouched), `WindowChecker.Exist(ps) []Existence` (one `Present`, `Gone`, or `Unknown` per placement, the backend grouping its questions), `Locator.Locate(stored, pid, getenv) (*jsonio.Object, error)` ("Finding a session's window": the placement of the window that answered, or an error naming each place asked), `Sender.Send(p, text, submit)`, and `Focuser.Focus(p)`. `ops` and `pick` reach a backend only through these, and turn a missing ability into `terminal` `unsupported` with the backend's tag (`ops.unsupported`, ability in `detail`); `hook.Call.Backend()` is the detected backend, and `terminal-sync` does nothing when it isn't a `Syncer`. `hook.Process.Backends` is the list `Call.Backend()` detects from, nil meaning `backends.All()`: only tests set it (`internal/hook/backend_test.go` checks a backend without sync, one with it, the detection order, and tmux). kitty is the only entry in the list; `internal/placement/placementtest` is not in it.
- **The kitty backend** is `internal/placement/kitty`, and `kitty.Backend{}` is its `placement.Backend` with every ability; the tmux and screen rule it leaves to its caller is `placement.Multiplexed(getenv)`, which `Detect` and `record` both call. `Recognize(getenv)` returns the placement, or nil; `RecognizeParsed(getenv)` returns the same as `Parsed`, kitty's own socket and window ID. `Call.RecordEnv()` passes the detected backend's `Replace` as `Env.Placement` to every verb, so a session adopted late in kitty is placed; `record` still lets only `SessionStart` replace one. `Replace(next, old)` keeps `tab_title` and `user_vars` as the design spec says. `Parse(p)` is the validation.
- **`kitty.Sync(socket, window)`** runs `kitten @ --to <socket> ls` (`--to` is an option of `kitten @`, so it comes before `ls`) through `exec.CommandContext`, with a 1-second deadline, `cmd.WaitDelay` of 100ms, stdout in a buffer, and this process's environment: `kitten` is found on this process's `PATH`. It returns `Synced{TabTitle, UserVars}` from `ParseLS`, a pure function: the list of OS windows, each with `tabs`, each with `windows`; it takes the `title` of the tab holding the window `id`, and that window's `user_vars` (empty when absent). Other keys are ignored. Every failure is a `*kitty.Error` whose `Timeout` says whether the deadline passed (its `TimedOut()`, which `placement.IsTimeout(err)` reads); that is the one `terminal-sync` logs. `ParseLS` scrubs the tab title and each `user_vars` value. `kitty.Apply(placement, synced)` returns the placement with the synced keys, and whether that changed it, for the write under the session lock.
- **Step 5 lives in `sesshin.go`**; `sync.go` is the only other code that names `sesshin.json`. A file with an ID is left alone, except that `SessionStart` replaces its placement, and writes only if the bytes change. A missing, corrupt, or null-`id` file takes the state lock, issues `last_id + 1` with `PublishSynced`, and writes `sesshin.json` before releasing the lock. If the ID can't be issued (the lock's wait ran out, `state.json` can't be read or written, or `sessions/` can't be listed), the cause is logged; a file that is missing or corrupt is written with a null `id`, and a null-`id` file that exists takes `SessionStart`'s replaced placement, written only if it changed; the next lifecycle hook completes it. What `pending` did is logged after the write: `sesshin.json written without an id`, `keeps no id`, or `not written`.
- **IDs.** A `state.json` that is missing or corrupt restarts from the highest `id` in any `sesshin.json` when `sessions/` holds another session (a directory that is not hidden and not this one), logging `last_id rebuilt from N` once `state.json` is written; with no other session it is a first run. A corrupt one is logged as well; one in another format issues no ID, logged only from `session-start`. One that can't be read (a read error other than `ENOENT`) is logged and issues no ID: `sesshin.json` is written with a null `id`, as when the state lock's wait runs out. When `sessions/` can't be listed, a first run can't be told from a loss, so no ID is issued: `sesshin.json` is written with a null `id`, as when the state lock's wait runs out, rather than risk issuing an ID already in use.
- **The Adopt rules** ([Creating `sesshin.json`](hooks-spec.md#creating-sesshinjson) step 3, and `session-start`'s adoption on resume) are in `record`, `adopt.go`, under the state lock `completeSesshin` already holds; `Env` reads `SESSHIN_JOB` and `SESSHIN_TOKEN` through `Getenv`, checked with `model.IsJob` and `model.IsToken`. A reservation is found by `model.ReservationName(job, token)`, built from `SESSHIN_JOB` (or none) and `SESSHIN_TOKEN` and opened directly, never by a scan; whether a job is held by a reservation lists `reservations/` for names that parse with its key. Every held-job comparison, here and in `ops`, is of keys. A reservation is read with `model.ReadReservation` and judged by `ReservationFile.Staleness`, whose two limits live in `model` beside the reservation type, so `ops` and the hooks can't drift. Rule 3 reads every visible session directory with a UUID name through the `sessions/` root held for the state lock: `lifecycle.json`, `statusline.json`, and `sesshin.json` with `model`'s readers, a missing or unusable file read as missing, with nothing logged; then `live.Derive` and `live.Jobs`. This session is read too, so Liveness rule 3 can supersede an earlier session of its process, but it is never the holder. Its process start times come from `proc.StartedAt` (`Env.StartedAt` in tests). The reported-job rule is `live.Jobs(sessions, results, jobs)`, which `ops` and `record` both call, so readers and hooks judge a held job the same way.
- **The deadline** is `Env.Deadline`, set by the hook ([Locks](#locks)); `Env.wait()` is each lock's wait.
- **Tests** are in-process on temp directories through `fsys.OS`, with `fsys.Fault` for injected errors and renames: every row of the effects table and each qualifier's guard, the straggler guard, adoption, each Adopt rule (nested, a fresh and a stale matching reservation, a job held by a live, an `unknown`, and an ended session, a fresh reservation of another token, a malformed `SESSHIN_JOB` or `SESSHIN_TOKEN`, a pending `id` completed with its job decided) and adoption on resume, unusable files, the locks and the deadline, IDs, a seeded property test that every file written reads back through its `model.Read*`, and 8 writers × 100 events in goroutines with separate roots.

## List and show

`ops.List(in, env)` and `ops.Show(in, env)`, from [`list`](operations.md#list), [`show`](operations.md#show), and the shared rules they follow ([Reading the sessions](operations.md#reading-the-sessions), [Narrowing](operations.md#narrowing), [Session order](operations.md#session-order)). `env` is a `ReadEnv`, the one `prune` takes too: the `fsys.FS`, `getenv`, the OS name, `Now`, and a `live.StartedAt`; `OSReadEnv` is the real one. Both take no lock, and write nothing, not even the state directory.

- **The reported job** (design-spec [Reservations](design-spec.md#reservations)) is `live.Jobs`, derived after `live.Derive`, over every session read, not only those the narrowing keeps: among sessions whose liveness is `live` or `unknown` storing one job by key (`model.JobKey`, ASCII `A`–`Z` lowercased), the earliest `last_start_at`, then the lower UUID, reports it, and the others `null`. An ended session reports what it stored. `show` derives it over the whole read as well.
- **One reader, shared with prune** (`internal/ops/sessions.go`). `readSessionFiles(root, dir, id, withSesshin)` reads one session directory through its root: `lifecycle.json` and `statusline.json`, and `sesshin.json` when asked (prune's rejudge reads it itself, and prune never asks). It returns a `live.Session`, the `sesshin.json` read, and a list of `fileIssue`s: which file was missing (`lifecycle.json` only) or unusable, at what path, and why; a file past `MaxRead` or a directory in its place is unusable (`unusableRead`), as in a malformed one. Each caller turns the issues into its own warnings: prune warns for `lifecycle.json` only and says "the session is kept"; `list` and `show` warn for all three files. `readSessions(env)` is the walk both use, reading no config: `sessions/` opened once (missing is no sessions), each visible directory with a UUID name read, `live.Derive` over the sessions with a usable `lifecycle.json` together, and the result sorted by `compareOrder`. A session with no usable `lifecycle.json` is skipped, with a warning when the file is there; a directory that vanished (`Moved`) is skipped without one. The clock is read once, for `Derive` and the prompt cache alike.
- **The view** (`internal/ops/view.go`). `SessionView` is the session view as a struct, its fields in the schema's order; `viewFields`, which `fields` is checked against, is read from its JSON tags by reflection, so the struct is the one list. A pointer is `null` when nil. A `fields` projection is `SessionView.project`, an ordered `jsonio.Object` of the members asked for, in the view's order. The `statusline.json` payload is encoded back to bytes and decoded by `payload.Decode`, the statusline's own reading (so `cost`, `context_window`, `prompt_cache`, and `session_name` read exactly as it does, and a value of the wrong type is `null`); only what the view alone needs (`hit_ratio`, `misses`, `last_miss_cause.causes`, `rate_limits`) is read from the stored tree. `sesshin-hook` never links any of it: `ops` imports `statusline` for `CacheState`, and nothing in `payload` changed. A payload number is an integer in the view when it is whole and within 2^53 − 1, else `null`. `expires_at` is the Unix time with its fraction dropped, formatted as a timestamp, only while warm and only when a timestamp can hold it. `transcript_exists` is `FS.Stat` of an absolute `transcript_path`: `true`, `false` on `ENOENT`, else `null`.
- **Selectors.** `parseSelector` is the one parser, which `show`, `resume`, `send`, `focus`, and `update` all use: `self` is checked first (it also matches the job form), then all digits is a sesshin ID (no leading zero, at most 2^53 − 1), then 8 to 36 characters of hex digits and hyphens, lowercased, is a UUID prefix, then `job:` and a job name, or a job name alone, is a job. A `Selector` has `Self`, `ID`, `Prefix`, and `Job`. `Self` is resolved before matching by `proc.FindCaller`: the nearest ancestor of this process that is `CLAUDE_PID` or a `claude` by the walk's name rule. Unlike a hook's `proc.Find`, it takes `CLAUDE_PID` at any depth, since a command in a pipeline or under `xargs` sits deeper than a hook; then it finds the session whose `pid` and `pid_started_at` match and which is that process's live session after `live.Derive`; none is `not-found`, and from then on it matches as a sesshin ID would. It matches a session with a usable `lifecycle.json` by its sesshin ID, by `strings.HasPrefix` on its UUID, or by the job it reports: `Selector.choose` takes a job's first session in session order among those reporting it (`sessionRec.job`), which is the live one if any, else the last seen, among the sessions the operation selects from. The schema's pattern for a job has a lookahead after an optional literal (`^(job:)?(?![0-9]+$)…`), which `schematest` reads as the pattern with, or without, the literal removed. `show` takes the matches of the whole read in session order, so `ambiguous` lists its candidates as `list` would. `show`'s `unusable-file` warnings are those of the selected session and of the sessions that might have matched (every `lifecycle.json` and `sesshin.json` for a sesshin ID or a job; those of the sessions the prefix could name), and go with `not-found` and `ambiguous` as well. `list` warns of every unusable file of every session, whatever the narrowing left out.
- **Output encoding.** `ListOutput.Sessions` holds `SessionView`s or projections; `ShowOutput.StatuslinePayload` is the stored payload (`model.Payload`, written back with its key order and number text), `null` as an explicit `json.RawMessage` without a usable `statusline.json`, and left out without `include_payload` (`omitempty` on an `any`). `last_miss_cause` is a pointer to a non-nil slice, so the writer's no-nil-collections rule turns no one into `[]`.
- **Tests:** `internal/ops/list_test.go`, in-process over a temporary `HOME`, as `prune`'s are, with the fixed clock and fake process table: every input check, each error kind and the order of the first three, the empty and missing directories, ignored entries, session order and its ties, each narrowing (including a warning for a session narrowed away), `duplicate-id`, each warning case, each derivation (name, model, pid, pending, attention, metrics with wrong types, the prompt cache's states, `transcript_exists`, `superseded`), every selector form, `ambiguous` with and without truncation, and the payload. Each envelope is validated with `checkEnvelope`, a projected `list` included (`list-output` takes a `session-view` or a `session-projection`), and a projection's members are also checked against the full view's. `e2e/list_test.go` runs the built `sesshin list` and `sesshin show` over sessions made by `sesshin-hook`, `internal/cli/args_test.go` the positional argument and the list option.

## The settings.json proposal

sesshin never writes Claude Code's `settings.json`. `install` and `uninstall` read it, and write the file they propose to `<state>/settings.proposed.json` with the atomic write above, for you to apply ([`install`](operations.md#install)).

`internal/settings` is pure: no file I/O, no envelope, no `install.json`. `Parse` reads the bytes into the ordered tree and returns a `*CorruptError` (with a `detail` naming the key, as `hooks.Stop[2].hooks`) for a read failure, nesting past 64, a repeated key at a place sesshin reads (`hooks`, an event, a group's `matcher` or `hooks`, a hook's `type` or `command`, `statusLine` and its `type` and `command`; a repeat anywhere else is the user's and is kept), or a sesshin-relevant key of the wrong shape; an absent file is `Empty()`. `ProposeInstall(tree, hookBinary, sesshins)` and `ProposeUninstall(tree, sesshins)` take a predicate for the paths that are `sesshin-hook`, copy the tree, and return the proposed tree, the `changes` in operations' Order, and for install whether a `statusLine` that wasn't sesshin's was replaced. `Marshal` writes the tree with `jsonio.MarshalFile`: two-space indent, the File format's escaping, key order and number text as read.

- **Word splitting** is POSIX's for single quotes, double quotes (with ``\$ \` \" \\ \newline``), and a backslash outside quotes, and conservative about the rest: unquoted `$`, a backtick, `*?[`, `{ }`, `;|&<>()`, a newline or other control character, a `~` or `#` that starts a word, or a leading `name=value` word, and `$` or a backtick inside double quotes, make the command not sesshin's. A command is sesshin's when it splits into exactly `[P, verb]` with `P` passing the predicate. A hook that isn't an object, or has no string `command`, is not sesshin's.
- **Quoting** writes `P` as is when it holds only `A-Za-z0-9/._-`, else in single quotes with each `'` as `'\''`; a property test checks that splitting a quoted path gives it back.
- **The registration table** is data in the package, in the hooks spec's order. Of sesshin's entries for a registered event and verb, the first in `settings.json` order is kept: **unchanged** when its whole group is byte-identical to the group sesshin writes (same keys in sesshin's order, same number text), else **replaced**. A replaced hook that is the only one in a group whose matcher is `""` or absent has its group rewritten in place; any other is taken out of its group, which keeps its other hooks, and sesshin's own group is appended to the event's array. A registered command with no entry is **added**, appended the same way. Every other sesshin entry (a repeat, one under an event sesshin doesn't register, one with a verb not registered for its event) is **removed**. A group, event, or `hooks` that a removal emptied is removed; one that was empty before is left alone.
- **`statusLine`** is added when absent. When sesshin's, the user's other keys (`padding`) are kept and only `type` and `command` set: unchanged when both are already sesshin's exactly, else replaced. One that isn't sesshin's is replaced wholesale, with the `status-line-replaced` warning. `uninstall` removes it while it is sesshin's, and reports a `statusLine` that isn't `unchanged`; an absent one has no item.
- **Permission rules** are data beside the registration table: the allow and ask rules in the hooks spec's order, every one of them sesshin's. Install appends each rule missing from its array (comparing whole strings; non-string items are skipped, not errors), creating `permissions`, `allow`, or `ask` at the end of their parent when absent; an item is `added` or `unchanged`. Uninstall removes every copy of each from its own array (`allow` or `ask`, per the table), then each array its removal emptied, then a `permissions` left empty, with one `removed` item per rule found. A `permissions` that isn't an object, or an `allow` or `ask` that isn't an array, is a `*CorruptError` naming the key. Tests: absent, present, duplicated, in `deny` only (still added to `allow`), a non-string item, the corrupt shapes, uninstall keeping the user's other rules (`Bash(jq:*)` among them), and the round trip (install then uninstall leaves the file as it was).
- **Everything else** keeps its place, value, key order, and number text. Proposing again from any proposal gives every item `unchanged` and the same bytes; a property test over generated settings checks it, and that the hooks of other tools survive both operations.

### Install and uninstall

`internal/ops` (`install.go`, `uninstall.go`, `setup.go`, `selftest.go`), over `internal/settings`. Both take an `ops.Setup`: the `fsys.FS`, `GOOS`, `getenv`, the executable (`os.Executable` with symlinks resolved by `filepath.EvalSymlinks`, the one call outside `fsys` besides the self-test's), the clock, sesshin's build information, and `SelfTest`, which is the real self-test unless a test replaces it. `ops.OSSetup` is the process's own; the CLI's `Env.Setup` is nil there, and tests set it.

- **Shared helpers** (`setup.go`): `resolve` (`environment`), `readSettings` (through `FS.ReadFile`, following a symlink; `ENOENT` is `settings.Empty()`, any other error `io`, a `*settings.CorruptError` `corrupt` with `Path` set), `readInstall` (missing or unusable reads as missing; any other read error is `io`), the `sesshins` predicate (the `sesshin-hook` beside this `sesshin`, the `hook_binary` `install.json` records, or any path `settings.SesshinHookName` accepts), `writeProposal`, and `shellQuote`. `install` reads `install.json` before it writes the new one, so the entries of the install being replaced are sesshin's.
- **The proposal** is written with `fsys.Publish` through a root opened with `fsys.OpenRootCreate` on the state directory, so a missing state directory is created; `install.json` is published the same way, first. `apply` is exactly two strings, `diff -uN '<settings>' '<proposal>'` and `mkdir -p '<settings dir>' && cat '<proposal>' > '<settings>'`, every path single-quoted with each `'` as `'\''`, whether or not it needs it (unlike a hook's command, which quotes only when it must). The proposal is written even when nothing changes, and by `uninstall` even for an absent `settings.json` (then `{}`). `changes` is never null; `proposal_path` and `apply` are, with `dry_run`.
- **The self-test** is `ops.SelfTester`, in `internal/ops`, so `sesshin-hook` never links it. Its seams are fields: `FS`, `GOOS`, `Environ`, `ReadBuild` (`buildinfo.ReadFile`), `TempDir` (makes the temporary `HOME` and returns the function that removes it, deferred), and `Child`, which runs one verb. Tests stub `Child` with a function that plays the hook and writes files under the `HOME` it was given, and replace `Setup.SelfTest` wholesale to test `install` around it. The real `Child` is `exec.CommandContext` with a limit of `ops.ChildLimit` (10 seconds, the hooks' registered timeout) and `cmd.WaitDelay` of 100ms, so a grandchild holding the pipes can't stretch it; past the limit the child is killed and the verb fails. A child that can't be started fails its verb too (`detail` says so), not `io`.
- **What is checked, and who is named.** `sesshin-hook` missing, not a regular file, not identifiable, or another build: `hook: null`, before anything runs. A verb that exits non-zero, writes to stderr, is killed by a signal, or runs past the limit: that verb. Then `lifecycle.json` and `sesshin.json` (valid, `id` 1) are checked against `session-start`, and `statusline.json` and the printed line against `statusline`, each the verb that was to write it. The state directory is the child environment's, resolved with `loc.Resolve`.
- **Tests:** in-process, `Setup` over a temporary `HOME` containing a space and a quote, with `SelfTest` stubbed; every error kind in its precedence; `dry_run` against a snapshot of the whole tree; the self-test's checks one at a time against the stubbed `Child`, and the real `Child` against shell scripts. `e2e/setup_test.go` runs the built binaries: install, apply, a `dry_run` that is all `unchanged`, uninstall and apply with another tool's entry surviving; and the self-test refusing sesshin alone, a script, a build with no version information, another build, and a `sesshin-hook` that exits 0 without recording. The tests that need an identifiable build skip when `sesshin version` has neither a commit nor a version (a checkout `go build` can't stamp).

## Spawn

`ops.Spawn(in, env)`, from [`spawn`](operations.md#spawn), [Launching `claude`](operations.md#launching-claude), and design-spec [Reservations](design-spec.md#reservations). `env` is a `SpawnEnv`: a `ReadEnv` (the `fsys.FS`, `getenv`, the OS name, `Now`, `live.StartedAt`, `Backends`), plus `Token` (32 lowercase hex characters from `crypto/rand`; tests: fixed), and `Sleep` for the wait's 100 ms polls (tests: advances the fake clock). `OSSpawnEnv` is the real one. Nothing in `ops` runs a process itself.

- **Constants,** in `ops`: the claim's and the record's state-lock waits ([Locks](design-spec.md#locks)), the poll (100 ms); in `kitty`: the launch limit (10 s), with a `WaitDelay` of 100 ms as `ls` has. The reservation limits are `model`'s.
- **Before any lock,** in the Errors table's order: `DecodeSpawnInput` (schema, then Additional validation, every problem collected), `loc.Resolve`, `config.Read` (for `spawn_shell`), `cwd` by `FS.Stat` (missing, or not a directory: `not-found` with `paths`), then the backend: `placement.Detect(env.Backends, getenv)`, else `terminal` (`unavailable`); a backend that isn't a `placement.Launcher` is `terminal` (`unsupported`), and so is one whose `UserVars()` is false when `vars` isn't empty, both before anything is reserved. With a `job`, the reservations of its key (`model.ReservationName` parsed over a listing of `reservations/`, through a root on it; missing is none) are read, and for each usable, launched one not stale by `model`'s `Staleness`, the backend's `WindowChecker` is asked, once for all of them (kitty asks one `ls` per distinct socket; none, or a failure, is `Unknown`).
- **The reservation** reuses prune's machinery, with a job or without: `Lock(500ms)` on the `sessions/` root (creating `sessions/` if missing, as the hooks do, so the lock has a directory), `EAGAIN` is `busy` (`lock`: `state`). Under it, with a job, `readSessions`' walk (factored so it can run on the held root) gives liveness and `live.Jobs`; a live or `unknown` session reporting a job with the job's key is `conflict` (`job-taken`, `sessions` its ref), its message naming the stored job when it differs (`the job api is held, as API`). The job's reservations are read again; `windowGone`'s token-and-placement guard decides whether the earlier answer counts. A fresh one is `job-taken` with empty `sessions`; stale ones are removed. Then the new file, `model.ReservationName(job, token)` (`<key>_<token>.json`, or `<token>.json` with no job), is written with `fsys.Publish` through an `OpenRootCreate` root on `reservations/`, `extra` as given (its `*jsonio.Object`, order and numbers kept) or `{}`.
- **The launch,** `Launcher.Launch(placement.LaunchSpec)` (kitty's is `kitty.Launch`): the caller's placement (`LaunchSpec.Caller`; kitty reads its socket), `type`, `cwd`, the title (`name`, else the job), vars, `SESSHIN_TOKEN` and, with a job, `SESSHIN_JOB`, and the argument vector built by `ops.ShellArgv(spawnShell, args, prompt)`, with `--name <name>` put before `args` when there is a name or a job (pure: POSIX or fish by the base name of the first word, `--` before a prompt). It runs `kitten @ --to <socket> launch …` with `exec.CommandContext`, this process's environment for `kitten` itself, and returns the window ID or a `*kitty.LaunchError` that says `Unknown` (the limit, or stdout not a positive integer after trimming one trailing newline) or not (a nonzero exit, `kitten` missing). The placement returned is built as `Recognize` builds one, from the caller's socket and that ID.
- **After the launch,** the reservation is rewritten or removed under `Lock(2s)` only when its usable re-read holds this token; the rewrite keeps `job`, `token`, `created_at`, and `extra` and sets `placement`. A failed lock or write on the record path is the `placement-not-recorded` warning; on the `launch-failed` path it is ignored (the reservation then strands in 120 s), and the error stays `terminal`.
- **The wait** polls `readSessions` (no lock) until `start_timeout_secs` passes on the monotonic clock: with a job, the first session `live.Jobs` reports it for; without, the first whose stored placement is kitty's with the launched socket and window ID. The view is `show`'s for that session. Warnings from the last read only.
- **`spawn_shell`** in `internal/config`: `SpawnShell(getenv) []string` returns the configured array, or `[$SHELL, -l, -i]` when `SHELL` is absolute, else `[/bin/sh, -l, -i]`. An empty array, an empty string, or a relative first word is `corrupt`.

- **Tests,** in `internal/ops/spawn_test.go`, in-process over a temporary `HOME` with the fake clock, process table, and a `placementtest.Kitty` for `Windows` and `Launch`: every input check and the Errors table's order, and `unsupported` from a backend with no launch and one with no user variables (nothing reserved); the claim against a live, an `unknown`, and an ended holder, a fresh, a stranded, an expired, a window-gone (and a voided window answer), and an unusable reservation; the state lock held (`busy`); each launch outcome (`launch-failed` removes, `launch-unknown` keeps, success records, the record skipped when adopted or reclaimed, `placement-not-recorded`); the wait with and without a job, a timeout with `not-started`, and `start_timeout_secs` 0; and every envelope through `checkEnvelope`. `ShellArgv` has a table test, POSIX and fish, with a prompt beginning with `-` and arguments full of `$(…)`, quotes, and globs, and a test that runs the POSIX form through `/bin/sh` and checks the vector arrives intact. `kitty.Launch` is tested against the fake `kitten` (its argument vector, the `--env` sets and no other `--env`, `--self`, `--keep-focus`, the ID read, a nonzero exit, a hang past the limit, bad output). `e2e/spawn_test.go` runs the built `sesshin spawn` with the fake `kitten` answering a window ID, `start_timeout_secs` 0: the reservation written and then given its placement, the envelope, and `job-taken` on a second spawn of the job.

## Resume

`ops.Resume(in, env)`, from [`resume`](operations.md#resume) and [Selecting a session](operations.md#selecting-a-session). It takes spawn's `SpawnEnv` and shares its machinery: `internal/ops/launcher.go` holds the `launcher` that `spawner` and `resumer` both embed, with the caller's window (`terminal`), the job's reservation read without a lock (`reserved`), `claim`, `record`, `release`, and `failed` (the `launch-failed` and `launch-unknown` errors, which release or keep the reservation). Nothing in them differs between the two but the job (`launcher.job`, empty for none) and the sentence `claim` ends `job-taken` with, which for `resume` suggests `job`.

- **Input.** `DecodeResumeInput` takes `session` by `parseSelector` ([List and show](#list-and-show)), and `job`, `args`, and `start_timeout_secs` by the helpers `DecodeSpawnInput` uses (`decodeJob`, `decodeArgs`, `decodeStartTimeout`), so the two commands check them alike.
- **Before any lock,** in the Errors table's order: the input, `loc.Resolve`, `config.Read`, then the session. `readSessions` reads every session as `list` does. The selector chooses among all sessions for a sesshin ID or a UUID prefix, and among the ended ones for a job (`Selector.choose`, see [List and show](#list-and-show)); none is `not-found` (`selectors`), several `ambiguous` (the candidates as `show` builds them, factored as `noSession` and `ambiguous`), and one that is not ended `conflict` (`live`). Then `cwd`: unrecorded, empty, relative, or not an existing directory is `not-found` (`paths` empty, or the `cwd`); then the terminal and the job's reservation, as `Spawn` does. The job is `job`, else the selected session's reported one. The unusable files read while selecting are `unusable-file` warnings, which go with a selection that fails as `show`'s do. `transcript-missing` is judged from the session's view (`transcript_exists` `false`).
- **The claim and the record** are spawn's, over the same code. The claim's own read of every session under the lock adds warnings only for files not warned of already (`appendNew`).
- **The launch** is the caller's `Launcher.Launch` (kitty's is `kitty.Launch`) with type `tab`, the session's `cwd`, and `ShellArgv(spawn_shell, ["--resume", <uuid>, args…], "")`: no prompt, so no `--`. The title and variables come from `Stored(placement)` of the backend the placement's tag names (`ReadEnv.backendOf`; kitty's is `kitty.Stored`, which reads a placement as `kitty.Parse` does and returns its `tab_title` and `user_vars` in order), while the launch goes through the caller's; a placement its backend rejects, or one of a tag with no backend, gives neither, and the title is then the session's name. On a `Launcher` whose `UserVars()` is false the variables are dropped: `LaunchSpec.Vars` is empty unless `UserVars()`. An empty `tab_title` is none. `SESSHIN_JOB` and `SESSHIN_TOKEN` are set when there is a job.
- **The wait** polls `readSession` (`sessions.go`), which reads that one session's directory alone and derives its liveness and job over it alone (the walk's second half, `deriveRecs`, is shared), every `pollInterval`, until the liveness is `live` or `unknown`, as `spawn` counts it, or `start_timeout_secs` passes on the monotonic clock. The view is `show`'s. `not-started` adds the `session` ref to spawn's details. `start_timeout_secs` 0 returns with no read, no pause, and no warning.
- **Placement kept on resume.** `record.Env.Placement` takes `resumed` (the event's source is `resume`), and the detected backend's `Replace` (kitty's keeps `tab_title` and `user_vars` of a valid old kitty placement for any window then). `sesshin-hook` reaches a backend only through `Recognize`, `Replace`, and `Sync`.
- **The CLI.** `resume`'s table has one argument (`session`), the `--job` and `--start-timeout-secs` options, and `Rest` at `/args`, as `spawn`'s; it runs `ops.Resume` against the same `Env.Spawn`.
- **Tests,** in `internal/ops/resume_test.go`, over `spawn`'s fixture (temporary `HOME`, fake clock, process table, and a `placementtest.Kitty`): every input check, the Errors table's order, each launch field (type, cwd, title and variables from each kind of stored placement, the argument vector, the job variables), the job (stored, named, taken by a live session or a fresh reservation, free once stranded), the selector's job form for `resume` and `show` (bare, `job:`, a hex-looking job, a live holder, the last seen, never `ambiguous`), `transcript-missing`, the wait (that it reads only the session's directory, `not-started`, `unknown` counts as live, `start_timeout_secs` 0), the launch outcomes and `placement-not-recorded`, and the warnings; every envelope through `checkEnvelope`. `internal/record/resume_test.go` checks that the backend is told of a resume, `placement_test.go` that `Replace` keeps the keys for another window then. `e2e/resume_test.go` runs the built `sesshin resume` over a session made by `sesshin-hook` with the fake `kitten`, then the resumed session's own `session-start` in another window.

## Send

`ops.Send(in, env)`, from [`send`](operations.md#send) and [Selecting a session](operations.md#selecting-a-session). `env` is a `SendEnv`: a `ReadEnv`, whose backend is a `placement.Locator` (real: `kitty.WindowForPID` per socket; tests: a `placementtest.Kitty` answering from a table of sockets to pids to windows, recording what it was asked) and a `placement.Sender` (real: `kitty.SendText`; tests: records the call and answers as told). `OSSendEnv` is the real one, and `cli.Env.Send` carries a test's. It takes no lock and writes no file, and does not use `launcher`, since it claims nothing.

- **Input.** `DecodeSendInput` takes `session` by `parseSelector` ([List and show](#list-and-show)); `text` as a string that is not empty (the schema's `minLength`), then the Additional validation in this order: at most 1048576 bytes (`len`, not characters), valid UTF-8 (only the command line can supply anything else), and no control character other than tab, line feed, and carriage return. The reason names the first offender's class: ESC, a C0 control character, DEL, or a C1 control character. `submit` defaults to `true`, `force` to `false`.
- **Before anything is asked of kitty,** in the Errors table's order: the input, `loc.Resolve`, `readSessions`, the selection, then the checks. The selector chooses among all sessions for a sesshin ID or a UUID prefix, and among the live and `unknown` ones for a job (`Selector.choose`, as `resume` filters for the ended); none is `not-found`, several `ambiguous`; an ended one is `conflict` (`not-live`). The turn has ended when the view's `status` is `waiting` or `idle`; anything else, an unrecognized status included, is `mid-turn` unless `force`. The placement must pass its backend's `Valid` (any other placement, one with a tag no backend has included, and a missing or unusable `sesshin.json` are `no-placement`); the backend must be a `Locator` and a `Sender`, else `terminal` (`unsupported`); and the view's `pid` (`lifecycle.json`'s, else `statusline.json`'s) must be known, else `terminal` (`unreachable`) without asking kitty. The unusable files read are `unusable-file` warnings, which go with a failure too, as `show`'s do.
- **Finding the window.** kitty's `Locate` is `kitty.LocateVia(kitty.WindowForPID, …)`: the sockets are the placement's, then the caller's `KITTY_LISTEN_ON` when set and different. The lookup is made on each in turn: an error of any kind (the socket refusing, the 5-second limit, output not shaped as `ls`, no window with the pid) moves on to the next, and all failing is `unreachable`, with each socket's reason in `detail`. The window is never the stored one. `kitty.WindowForPID` runs `kitten @ --to <socket> ls` with `exec.CommandContext`, a 5-second limit and a `WaitDelay` of 100 ms, as `Sync` runs it (the same `ls`, under a limit it is given), and `kitty.ParseWindowForPID` is the pure part: the first window, in the order listed, with a `foreground_processes` entry whose `pid` is the session's. The window's own `pid` is the shell it started and is never matched.
- **The two calls.** `kitty.SendText` runs `kitten @ --to <socket> send-text --match id:<window> --bracketed-paste=disable --stdin` with `ESC[200~`, the text, and `ESC[201~` on stdin, and then, with `submit`, `kitten @ --to <socket> send-text --match id:<window> \r` (the two characters backslash and `r` as one argument, which kitten turns into CR). Each has a 5-second limit and a `WaitDelay` of 100 ms. A failed paste is a `*kitty.SendError` that sends no Enter; a failed Enter is one with `Submit` set. `ops` makes them `send-failed` and `submit-failed`; any other error from `Send` is `send-failed`. Neither is tried on another socket: the text may already be typed.
- **The output** is the session ref, `Address` of the placement `Locate` returned, `submitted`, and the view's `status`, `permission_mode`, and `event_seq`.
- **The CLI.** `send`'s table has the `session` argument, `--text` and `--text-file` (the `File` type, read exactly, as `--prompt-file`; both set `/text`, so both is the usage error that two options on one field already are), `--submit`, and `--force`. A new `OneOf` in the command table makes neither `--text` nor `--text-file` a usage error, unless `--input` is given; the empty file and the text with a control character or bad UTF-8 are `invalid-input` at `/text`.
- **Tests,** in `internal/ops/send_test.go`, over `spawn`'s fixture (temporary `HOME`, fake clock and process table) with a `placementtest.Kitty` for the lookup and the paste: every input check at its field and the schema's agreement; each control class, and the size limit counted in bytes (a text of fewer than 1 MiB characters but more bytes); the Errors table's order, with a session that breaks several rules; the selectors (a job among the live only, an ID or UUID of an ended session, a prefix shared with one); `waiting` and `idle` sent, `working`, `needs_approval`, an unknown status refused, each sent with `force`; every placement `no-placement` covers; an unknown pid (kitty not asked) and the statusline's pid; the socket order (the stored socket first, the caller's only when different and only after a failure, a socket asked once); `send-failed` and `submit-failed`, and that neither moves on; `submit` false making one call; the output fields; no file written; the warnings. In `internal/placement/kitty/send_test.go`: `ParseWindowForPID` over a listing of several OS windows and tabs (a pid in `foreground_processes`, not in a window's own `pid`, one of several processes, a prefix of a pid, a malformed listing), and the real calls against a fake `kitten` script that records its arguments and stdin: the exact argument vectors and bytes (a 1 MiB text, multi-line, multi-byte), no Enter after a failed paste, a failure on each call, a hang past the limit. `internal/cli/send_test.go` checks the command line (`--text-file` from a file and from stdin, both and neither, `--input`). `e2e/send_test.go` runs the built `sesshin send` over a session made by `sesshin-hook` and made live by a process of the test's own, with the fake `kitten` (which now also records the stdin of a call given `--stdin`): the three calls' arguments and bytes, the window found rather than the stored one, `--text-file -`, `--submit=false`, `force`, and each refusal with no text pasted.

## Extra

[`sesshin.json`](design-spec.md#sesshinjson)'s user-owned `extra` ([User-owned extra](design-spec.md#user-owned-extra)): handed to a session in its reservation, and changed afterwards only by [`update`](operations.md#update).

- **`extra` is a `*jsonio.Object`** in `model.SesshinFile` and `model.ReservationFile`, as `placement` is: the strict reader's ordered tree, numbers as `json.Number` with their text, written back in stored order. `model.ReadSesshin` and `model.ReadReservation` check it is an object within the limits (`model.ExtraMaxBytes` 65536, `model.ExtraMaxDepth` 32, depth counted from `extra`'s own object as 1); one past them makes the file unusable.
- **The hook side** (`internal/record`): no hook reads `extra` from the environment; `launchEnv` holds `SESSHIN_JOB` and `SESSHIN_TOKEN` only. `adopt.go`'s rule 2 returns the adopted reservation's `extra` with its job, and `completeSesshin` writes it into the file it creates or completes, as [Creating `sesshin.json`](hooks-spec.md#creating-sesshinjson) says (`freshExtra` is its `{}`). Adoption on resume never touches `extra`. Every other write of `sesshin.json` in `record` carries `Extra` through from what it read; a test writes each (placement replacement, resumed adoption, terminal sync) over a file with a non-empty `extra` and checks it is byte-for-byte unchanged.
- **The spawn side:** `spawn`'s `extra` goes into the reservation it writes (`{}` when absent), never into the environment; `launcher` sets `SESSHIN_TOKEN` always and `SESSHIN_JOB` with a job, as `placement.Var`s. The size limit is checked on the compact bytes (`jsonio.MarshalLine`). `resume`'s reservation has `extra` `{}`.
- **`update`:** `ops.Update(in, env)` mirrors koan's `update` for `extra` (koan `internal/ops/update.go`), with `env` a `ReadEnv`.
  - **The edit:** `replace_all` sets the object; `merge` calls `Object.Set` per key in input order (existing keys keep their position, new ones append); `remove` calls `Object.Delete`.
  - **Equality** as koan's (`internal/jsonio/equal.go`, brought over into sesshin's `jsonio`): objects regardless of key order, arrays in order, numbers compared exactly, never as `float64`, and never expanded: each is reduced to its significant digits and a power of ten (an exponent is a `math/big` integer), so `1e2` equals `100` and a huge exponent costs no more than a small one. An equal result writes nothing.
  - **The lock:** the session directory through `fsys`, `Lock(500ms)`, then the same identity check a hook makes after locking (the path still names the directory locked, else `not-found`). The re-read under the lock decides `no-sesshin-file`: `fsys`'s not-exist is `missing`; a read that fails validation is `unusable`, or `other-format` when `FileResult.OtherFormat` (its message from `Found`: older says `sesshin migrate`, newer says upgrade); a usable file whose `id` is `null` is `pending`; any other read error is `io`.
  - **The message** for `no-sesshin-file` is built from `file` and the session's liveness, as the [table](operations.md#update) gives it, naming the session by its UUID's first 8 characters and, for an ended one, the `sesshin resume <uuid>` to run.
- **The CLI.** `spawn` has `--extra`; `update`'s table has the `session` argument, `--extra-merge` and `--extra-replace-all` (JSON values, as koan's: `json.Valid`, then the strict reader; a bad token is `invalid-input` at its field), and `--extra-remove` (repeatable, one key each). With none of the three on `update`, the CLI builds `{"session": …, "extra": {}}`, and the operation reports the empty `extra` as `invalid-input`.
- **Tests.** `internal/model`: the limits (bytes and depth), numbers round-tripped (`1.10`, `-0`, `1e400`, a 20-digit integer), the integer-literal exemption; reservation names built and parsed, with a job and without, and rejected (`api.json`, a key that isn't the job's, a token that isn't the file's). `internal/record`: a fresh reservation's `extra` adopted on a fresh write and on completion, `{}` with no reservation, a stale one, or a nested session (whose reservation is neither opened nor removed), a job-less reservation adopted with `SESSHIN_TOKEN` alone, a `/clear` after adoption starting at `{}`, a pending file completed without a reservation keeping its `extra`, resumed adoption leaving `extra` alone, and every other write over a non-empty `extra` leaving it byte-for-byte unchanged. `internal/ops`: `spawn`'s `extra` checks and agreement, the reservation written with and without a job and no `SESSHIN_EXTRA` in the launch env, `resume`'s `{}`, `extra` in the view and projection; `update_test.go`, over `spawn`'s fixture: every input check and the schema's agreement (both `oneOf` forms, a shared key, empties, the limits counted in bytes and depth); each form's effect and key order; `changed` empty with no rewrite (the file's mtime and bytes unchanged) for an equal result, including `1.0` against `1` and keys reordered; numbers round-tripped; `extra-too-large` from a `merge`; the Errors table's order; `no-sesshin-file` for each row of its table (missing, unusable, and pending, live and ended) with its `file`, `path`, and message; a file that turns unusable between selection and the lock; a directory pruned while waiting (`not-found`); `busy` with the lock held; `io` for an unreadable file; `self` from inside a session and `not-found` outside one; every other key of `sesshin.json` untouched. `e2e`: `sesshin spawn --extra` (with the fake `kitten` recording `--env`), a session made by `sesshin-hook` with the reservation's `SESSHIN_TOKEN`, then a `/clear` session at `{}`, `sesshin update`, `sesshin list --fields extra`, and a resume, `extra` surviving each.

## Prune

`ops.Prune(in, env)`, from [`prune`](operations.md#prune) and [Retention](design-spec.md#retention). `env` is a `ReadEnv`: the `fsys.FS`, `getenv`, the OS name for `loc.Resolve`, `Now`, and a `live.StartedAt`; `OSReadEnv` is the real one, and tests give it temp directories, a fixed clock, and a fake process table.

- **The scan.** The cutoffs are computed first (`config.DaysBefore` for the days, and `now` less `RetainHeadless()`), then `sessions/` is opened once as a root; a missing one is success with nothing pruned, and prune never creates it. Each entry that is a visible directory with a UUID name is read through that root: `lifecycle.json` and `statusline.json`, each `nil` when missing or unusable. A session with no usable `lifecycle.json` gets an `unusable-file` warning, is kept, and is not passed to `live.Derive`. Everything is judged before anything is removed: when now is earlier than the newest `last_event_at` or `received_at` read, nothing is, and both cutoffs are `null`.
- **The rejudge.** `Derive` runs over the scan, and each ended session inside a window is a candidate, oldest last seen first. For each, prune opens its directory as a root, takes `Lock(0)`, and skips it on `EAGAIN` (`skipped_locked`). Under the lock it checks `Moved` (another prune renamed it), reads the two files again, and runs `Derive` over the first scan's sessions with this one's entry replaced by the fresh read, so rule 3 still sees the others. Still ended and in a window, it is renamed aside, after reading `sesshin.json` for its ID; otherwise it is kept. `dry_run` goes through the same locks and the same rejudge, and stops before the rename.
- **A failed rename** (`RemoveAside` returns an error) stops the run with `io` for that session's path. Sessions already removed stay removed and are not listed, so a rerun is safe; a removal that fails after the rename counts as pruned, and leaves a hidden directory.
- **Reads.** A missing file, or one that is past `MaxRead` or a directory, is unusable, like a malformed one; any other read error is `io`.
- **Reservations,** after the sessions, with every session lock released. `reservations/` is opened once under the state root; a missing one is no reservations. Each visible regular file whose name ends in `.json` is read; `model.ParseReservationName` splits a name into its key (or none) and token, and a name it rejects (an old `<key>.json`) is unusable. The reservation file type and its validator (the name's key equal to `model.JobKey(job)`, none when `job` is `null`, and its token equal to `token`) are in `model`, beside `sesshin.json`'s. Each removal is reported with its `file`. Before any lock, the launched reservations not stale by age are grouped by socket, and the backend is asked once per socket, through a seam on `ReadEnv` (`Windows(placement)`, real: `kitty`'s `kitten @ --to <socket> ls` with a 1-second timeout; tests: a fake), returning the window IDs it lists or no answer. Then `Lock(0)` on `sessions/`, the state lock; `EAGAIN` sets `reservations_locked` and ends the run. Under the lock each reservation is read again and judged: unusable, `expired`, `stranded`, or `window-gone`, by [Reservations](design-spec.md#reservations)' table (the limits are `model`'s; `window-gone` needs its `token` and `placement` unchanged since the first read). Removal is an unlink through the root; a failure is `io` for that path, and reservations already removed stay removed. The clock check covers `created_at` with the sessions' clocks, before anything is removed.
- **Tests** are in-process, through `fsys.OS`, with `fsys.Fault` to change a session between the scan and its lock and to fail a rename, and in `e2e/` with sessions made by the hooks and aged by rewriting `last_event_at`. Reservations are written by the test directly: each reason, a fresh one of each kind kept, a window answer voided by a changed `token` or `placement`, no answer from the backend, the state lock held, the unusable clock, `dry_run`, and ignored entries.

## Migrate

`ops.Migrate(in, env)`, from [`migrate`](operations.md#migrate) and design-spec [Migrations](design-spec.md#migrations). `env` is a `ReadEnv`, as `prune`'s.

- **Steps** are `migrate.Steps`, an ordered `[]Step` in `internal/migrate`, one file per step (`001_extra.go`). A `Step` has `N` (its number), `Name`, and `Files`: for each kind of file it covers, the `schema` it takes the file from and a pure function on the file's ordered tree (`*jsonio.Object`) returning the converted tree or an error. A step never imports `model`'s current file types, which change with later steps: it knows its old format from its own code, and only the final result is checked, by `model`'s current reader. A test checks that `Steps` is numbered 1, 2, 3, … with no gap, that each kind's steps form a chain from its oldest `schema` to `model`'s current version with no gap or overlap, and that `model.LatestMigration`, the constant `sesshin-hook` writes on a first run, equals the last step's `N`.
- **Converting a file** is `migrate.Convert(kind, data) (out []byte, changed bool, err error)`, with `kind` `migrate.State` or `migrate.Sesshin` and no I/O: parse the bytes strictly, read `schema`, apply each step that covers that kind from that schema up, in order, then marshal the tree in the File format and read it back through the kind's `model.Read*`. A file already at the current version, or of a kind no step covers, is `changed` false with `out` nil: not written. Failures are `*migrate.Error` with a `Kind`: `Corrupt` (not one JSON object, or no integer-literal `schema`, or `schema` repeated: left alone, not reported), `Newer` (`Found` is the version: left alone, an `unusable-file` warning), `Unconverted` (a step refused the file, no step takes its `schema`, or the result isn't usable: `Detail` is the reason listed). Nothing is written on failure. Step 1 writes `migration` as 0 in a converted `state.json`; `ops.Migrate` sets the latest under the state lock. Keys keep the order they had, so a file written in schema order stays in it.
- **The operation.** `Migrate(MigrateInput{DryRun}, ReadEnv)` in `internal/ops/migrate.go` is one `migrator` run, following the operation's Effects. Step 1 reads `state.json` by path with `ReadEnv.FS`, through `model.ReadState`: a `FileResult` with `OtherFormat` and an older `Found` is read again as a schema-1 tree for its `last_id` (0 recorded), and a newer `Found` is `unsupported-format`. Step 2 opens `sessions/` once as a root, and each visible UUID-named directory in UUID order through it (prune's walk, with `Moved()` checked under the lock), with `Lock(migrateLockWait)` (the [Locks](design-spec.md#locks) table's wait; a variable only so a test can shorten it); `sesshin.json` is read and passed to `migrate.Convert(migrate.Sesshin, …)`, and the result goes out with `fsys`'s one-step `Publish`. `migrate.Kind` has only `State` and `Sesshin`: no other file is converted. Step 3 takes `Lock(migrateLockWait)` on that same `sessions/` root, re-reads `state.json` through the state directory's root, and writes it with `fsys.PublishSynced`. A held lock (`EAGAIN`) is `busy`, with the session's UUID for a session lock; any other failure, and a file that can't be read (`EFBIG` and `EISDIR` included: it can never be converted, so the run stops and names it) is `io`. `dry_run` runs the same pass, locks included, and skips each publish. A `changed` entry's `id` is read from the converted `sesshin.json`. A `state.json` at schema 1 that no step can convert is listed in `unconverted` with its warning, and left as it is, so `migration` stays where it was. With `sessions/` missing, step 3 creates it to have something to lock (with `dry_run`, it takes no lock). A missing or corrupt `state.json` is rebuilt from the highest `id` of the `sesshin.json` files that are usable after step 2, unless one is in a newer format or unconverted (step 2 records those in `migrator.foreign`): it holds an ID the rebuild can't read, so step 3 writes nothing, lists the newer ones in `unconverted` (the unconverted ones are listed already), and `migration` stays where it was. With `dry_run` the same.
- **Migration status** for the other operations is `ops.migrationStatus(env)`: `state.json` read once, with no lock, into zero or one warning (`migration-pending`, `migration-ahead`, with `recorded` and `latest`). Every operation that [Migration status](operations.md#migration-status) names (`Update` among them) calls it first, then the operation proper (`listOp`, …), and puts the warning first in the envelope's warnings, a failure's included; `restart` and `jump` get it through the `list` they run. Every `unusable-file` warning carries a `reason`: `missing` (a session directory with no `lifecycle.json`, warned of only when its mtime is more than 60 seconds before the clock read for the operation; prune warns of it at any age), `unreadable` (an OS error, a file past `MaxRead`, a directory in its place), `corrupt`, or `unsupported-format` (`FileResult.OtherFormat`).
- **The hook side** needs no step code. `record` and `statusline` treat a result with `OtherFormat` as a file to leave alone: no write, no replacement, logged only as the [Log](hooks-spec.md#log) says. A hook that creates `state.json` writes `migration` as `model.LatestMigration` with no other session, and 0 when it rebuilds; every other write carries it through.
- **Tests.** Each step has a fixture directory, `internal/migrate/testdata/<NNN>-<name>/`, holding `before/` and `after/` state directories, written by hand from the old format with no real paths or costs: `001-extra` has a schema-1 `state.json`, sessions whose `sesshin.json` is at schema 1 with and without a job and a placement, one already at schema 2, one corrupt, one at schema 1 with a field the old format didn't allow (unconverted), and one at schema 3 (newer, left alone). A test runs `migrate` on a copy of `before/` and compares it with `after/` byte for byte, runs it again and checks nothing changed, and, through `fsys.Fault`, ends a run after each of its k writes in turn and checks that a rerun reaches `after/`. In `internal/ops`: every Effects case of step 1 (schema 1, missing and corrupt with and without sessions, unreadable, newer, past the latest), `busy` for each lock, a session pruned between the scan and its lock, a run ended after each of its writes by `fsys.Fault`, `dry_run` writing nothing, the output's order, and each operation's `migration-pending` and `migration-ahead` warnings. In `internal/record` and `internal/statusline`: a file at another `schema` is left byte for byte unchanged by every verb, logged only by `session-start`, and a state directory at schema 1 issues no ID, then issues one once converted. In `e2e/`: the built `sesshin-hook` running over a `before/` tree leaves it unchanged except for events of sessions already current, then `sesshin migrate`, then a hook completes a pending ID.

## Restart

`pick.Restart(in, env)`, from [`restart`](picker-spec.md#restart). It follows koan's `internal/pick` (the fzf seam, the version check, the undone options, `KOAN_PICK_OPTS`, the column padding, the end-to-end tests), and is much smaller, because fzf's stdout is the selection: no helper verb, no callbacks into sesshin, no session directory beyond the preview files. It composes `ops.List` and `ops.Resume`, each as its own call, and runs no operation of its own.

- **Input.** `pick.DecodeInput` takes `query` as a string and `args` by `ops.DecodeArgs`, the helper `DecodeSpawnInput` and `DecodeResumeInput` use, so the three check `args` alike.
- **Environment.** `pick.Env` is `ops.SpawnEnv` (what `resume` runs against, so a test gives the picker the same fake launch, clock, and process table as `resume`'s) and a `pick.System`: `LookPath`, `Output` (run a program for its output), `Environ`, `OpenTTY`, `RunFzf` (the picker's run: stdin from the lines, stdout captured as the selection, stderr to the terminal), and `CatchInterrupts`. `cli.Env.Pick` carries it; nil is the process's own.
- **The order of checks** is the Errors table's. `ops.CheckSetup` is `resume`'s `loc.Resolve` and `config.Read` (environment, corrupt); `findFzf` runs `fzf --version` with `FZF_DEFAULT_OPTS` and `FZF_DEFAULT_OPTS_FILE` removed from the environment (a bad option in either is `fzf-failed` where fzf really starts, not here), reads the first word without its `-` suffix as three numbers, and compares with 0.63.0; `userOpts` splits `SESSHIN_PICK_OPTS`; `ops.CheckTerminal` is the `launcher.terminal` that `spawn` and `resume` call (`placement.Detect` over `ReadEnv.Backends`, then the backend's launch ability), so the picker and `resume` can't disagree; then `ops.List` with liveness `ended`, whose failure is returned as it is. With no candidates the run ends there, with `OpenTTY` unasked. Only then is `/dev/tty` opened (`no-terminal`), the preview directory made, and fzf run.
- **Lines.** `renderLines` builds one line per `SessionView` `list` returned, in `list`'s order: the UUID, a tab, and the columns joined by two spaces, each but the last padded with `runewidth.FillRight` to the widest. `scrub` replaces every control character (`unicode.IsControl`: tab, newline, escape, NUL, DEL, the C1 range) and U+2028 and U+2029 with a space in every field, the reason word included. A session's cwd is shortened to `~` only at a path boundary (`/home/pp` is not under `/home/p`). The relative time is the difference from `ReadEnv.Now`, floored, negative as `0s`.
- **Preview.** `newPreviewDir` takes the picker's name and the function that writes one view's file (`preview` here), and makes `sesshin-<picker>-<16 hex>` under `$XDG_RUNTIME_DIR`, else `$TMPDIR`, else `/tmp` (absolute), mode 0700, through `fsys` (`Mkdir`, then `Publish` of one file per UUID); a failure is `io`, with what was made removed. `preview` writes each row as `%-16s %s` over the label and its colon. `Remove` deletes the directory with `RemoveAll`, deferred in the function that runs fzf, so it is gone as soon as fzf returns, before the resumes, on every path; the one way to leave it behind is the crash the spec accepts. The preview command is `cat -- '<dir>'/{1}`, with the directory single-quoted and `--with-shell 'sh -c'` so that fzf quotes `{1}` itself.
- **Reading the selection.** Each stdout line is cut at its first tab, and the key looked up among the offered UUIDs; the picks are the offered sessions whose key appeared, in list order. A key repeated, or not offered, changes nothing. The exit status is judged after the run: 0 reads the selection, 1 is an empty `actions`, 130 is `cancelled` (details `{}`), any other is `unavailable` `fzf-failed` with `status`; a run that could not start, or ended by a signal, is `fzf-failed` without one.
- **The resumes.** Each pick is `ops.DecodeInput` over `{"session": <uuid>, "args": <args>, "start_timeout_secs": 0}`, then `ops.Resume` against the same `SpawnEnv`; the envelope goes into `actions` whatever it holds, and the next pick runs. Nothing is retried or cut short, and `restart` is `ok` once it got this far. The load's warnings are the envelope's.
- **Signals.** `CatchInterrupts` is `signal.Notify` for SIGINT and SIGQUIT into a channel of one that nothing reads, undone by `signal.Stop` when fzf returns: the first signal fills the channel and the rest are dropped, so all are discarded, with no goroutine ([H5](hooks-spec.md#the-contract)'s guard test forbids `go` statements in sesshin's code, where koan's drains the channel in one). It catches rather than ignores, since an ignored signal stays ignored in everything fzf starts (the preview's `cat`). Before and after fzf the default handling stands, and a Ctrl-C during the resumes is a crash, as the CLI spec says.
- **CLI-only kinds.** `unavailable` and `cancelled` are `ops.Error` values built in `pick` (`KindUnavailable`, `KindCancelled`); the envelope's `kind` is any string. Both exit 1, as every operation error does; only `usage` exits 2.
- **The disk.** The picker's files go through `fsys` like every other. The one thing outside it is `OpenTTY`, which opens `/dev/tty` and closes it at once: a terminal check, not a file operation on sesshin's data.
- **Where it is linked.** `pick` is in the `forbidden` list of the `sesshin-hook` dependency test with `cli`, `ops`, and `placement/placementtest` (which a test of its own keeps out of every binary): neither it, nor go-shellwords or go-runewidth, can reach a hook.
- **Testing,** in `internal/pick`: the lines, every End word, relative times, `~`, padding with wide characters, scrubbing (a tab, a newline, a forged UUID, line separators, an escape) and a forged key fzf prints, the preview files and the preview command run by the fake, the options (with `FZF_DEFAULT_OPTS='--select-1 --exit-0 --expect=esc --print-query'` in the environment, which the undone options placed after it counter), each outcome row, the resumes in line order with `job-taken` for the second of two picks storing one job, a failing resume not stopping the rest, the Errors order step by step (each failure made while every later one is still there), the version check, and no candidates without fzf or a terminal. The **fake fzf** is a shell script on a directory the test's `LookPath` serves: it records its arguments (NUL separated), stdin, and environment, copies the preview directory and runs the preview command on the first line's key, prints a selection file and exits with a status file's number. Every envelope is checked against `envelope`, `error`, `warning`, and `restart-output`, and every input against `restart-input`, as `resume`'s are. `internal/cli/restart_test.go` checks the command line and runs the real picker against a stubbed `System` (the exit code of `cancelled`, of `unavailable`, and an empty `actions`).
- **The Extra column's cases,** shared with `jump`'s lines: `{}` and `null`; each scalar kind; numbers' text kept (`1.10`); nested objects and arrays; keys needing quotes (a space, `=`, a non-ASCII letter, empty); values needing quotes (a space, NBSP, U+2028, `=`, `"`, empty, control characters); `<>&` unescaped; stored key order. A hostile value (a tab, a newline, ESC, U+2028, a forged UUID) stays on one line under its own key. The cap: a long ASCII value, and cuts next to `♨️` and next to a ZWJ emoji, each end within 200 columns with `…`, and so does one whose DEL and C1 characters widen it only once scrubbed. In both pickers' lines: Extra last, two spaces after Name; a name over 32 columns pushes only its own Extra; a line with an empty Extra, and every line when no candidate has one, has no trailing spaces. In `restart`'s preview: the `extra` block last, whole and indented for a value past the cap; an `extra` row of `—` for `{}` and `null`; a newline in a value as `\n`, not a line break; DEL, U+0085, and U+009B as `\u007f`, `\u0085`, and `\u009b`, none of them raw in the file.
- **The end-to-end test** (`e2e/restart_test.go`, with `e2e/pty_test.go`) runs the built `sesshin restart` in a pseudo-terminal (`creack/pty`, the screen rendered by `vt10x`) against a real fzf, with the fake `kitten`: type `killed`, ctrl-a, Enter resumes the one killed session of two, with the claude args after `--` in the launch; Esc is `cancelled` with no launch; both with the hostile `FZF_DEFAULT_OPTS`. `SESSHIN_E2E_FZF` lists fzf binaries separated as `PATH` is, and the test runs once per binary; unset, it uses the `fzf` on `PATH`, and skips without one. `scripts/fetch-fzf.sh DIR` downloads 0.63.0 (the minimum) and the current release (0.74.4) after checking their sha256, and prints the paths for the variable. No fzf, no test: `go test ./...` stays green on a machine without one.
- **The reboot,** a manual check, as the hooks' verifications are done: sessions in a scratch kitty instance, killed with it, come back with `restart`, `killed` and first.

## Jump

`pick.Jump(in, env)`, from [`jump`](picker-spec.md#jump). It shares [Restart](#restart)'s fzf seam, check functions, undone options, and `runSelection` (the run of fzf and the reading of its keys, with the outcome table), and differs where the spec does: it composes `ops.List` (liveness `live`) and `ops.Focus`.

- **Input and environment.** `pick.DecodeJumpInput` takes `query` as a string. `pick.JumpEnv` is an `ops.FocusEnv` (what `focus` runs against: the read environment, the window lookup, the focus call) and the same `pick.System`, which gains `ShowFailure`. `cli.Env.Jump` carries it; nil is the process's own. `findFzf` takes the picker's name for its messages.
- **The order of checks** is the Errors table's: `ops.CheckSetup`, `findFzf`, `userOpts`, the load, then `/dev/tty` (`no-terminal`) only with candidates, then the sort, the lines, and the preview directory (`io`), then fzf. There is no `ops.CheckTerminal`: `focus` needs no tab opened. With no candidates the run ends with `OpenTTY` unasked and fzf not started.
- **The order of the candidates** is `compareJump`, a pure three-way comparison over two session views, applied once with `slices.SortStableFunc` to `list`'s own order, so ties keep session order. It reads `attention`, `prompt_cache.state` and `expires_at`, and `last_event_at`; a nil attention counts as `unknown`, a nil `prompt_cache` as an unknown cache, and a warm cache with no `expires_at` (a time no timestamp holds) sorts after the warm ones that have one.
- **The lines** are `renderJumpLines`. The Cache column is `statusline.CacheText`, the function that `promptCacheSegment` also calls, so the two cannot drift; jump gives it the view's state, its `expires_at` parsed, its `recache_tokens`, and the location of the clock it was given (the process's local time, in the shipped build), and shows `—` for the empty string it returns. Widths are `cells`: `runewidth.StringWidth` plus one for each U+FE0F that follows a character it counts as one cell, since go-runewidth counts a text-style character made an emoji by U+FE0F (the ♨️ of a warm cache) as one, where the terminal draws two; every other emoji it already counts as two. Quiet is `elapsed`, the same helper as restart's `ago`, without the word.
- **The preview** is `jumpPreview(v, now, home)`, written by `newPreviewDir` with the name `jump`, after the sort and with the `now` `renderJumpLines` was given, so a file and its line can't disagree. It shares restart's row writer, `scrub`, and `extra` block (`jsonio.MarshalFile`, then `escapeC1`). Its rows map to the view as follows:
  - `attention`: the mark from `marks` and `attentionOf`; `status`; `liveness` only when it is `unknown`; `quiet`: `elapsed`, as the Quiet column; `stall_reason` when non-nil; `pending` when non-nil with either count above 0.
  - `cache`: `cacheColumn`, the Cache column's own function.
  - `hit ratio`: `hit_ratio` × 100 through `statusline.Percent`, exported from `percent` so the rounding is the statusline's; then `misses` and `last_miss_cause` (an empty slice counts as nil).
  - `context`: `statusline.ContextText`, split out of `contextSegment` as `CacheText` was out of `promptCacheSegment`. It takes the percentage and the two counts as `payload.Num`s and returns them without the emoji, the percentage as `""` when missing. `contextSegment` puts `🧠` before it and keeps its `0%` fallback; the preview puts `—` in its place.
  - `cost`: `metrics.cost_usd` and `burn_usd_per_hour`, each `%.2f`; a nil `metrics` makes the row `—`.
  - `session`: `#<id> <name>`, the name alone when it is `"#"+id` or `id` is nil; `tab title` from the placement's backend's `Stored` (`ReadEnv.TabTitle`), as restart's.

  The parts-stand-alone rule (a nil part left out, or `—` before a part that is shown) is one helper the three composite rows share.
- **The options** are `jumpArgs(dir, query, opts)`: the undone options, `--with-shell 'sh -c'`, `--no-multi`, `--no-sort`, `--delimiter`, `--with-nth`, `--preview` with restart's `cat -- '<dir>'/{1}`, `--preview-window 'down,50%'`, `--query`, then `SESSHIN_PICK_OPTS`. No `--multi`, no `ctrl-a`; restart's `args` is unchanged.
- **The focus** is `ops.DecodeInput` over `{"session": <uuid>}`, then `ops.Focus`; the envelope goes into `actions` whatever it holds. The first key fzf printed is the pick; one not offered is ignored.
- **Showing a failure** (step 6) is after the envelope is written, so it cannot be inside `Jump`: the `jump` command registers `pick.ShowFailure(envelope, sys)` with `Env.after`, and `cli.Run` runs what was registered once `deliver` has written stdout and closed it, and not at all when the result was not delivered (exit 3). When `pick.WillShowFailure` says it will show, the command also calls `Env.showsFailure()`, and `Run` drops the stderr note of a failed envelope. `ShowFailure` decides (`failureMessage`: a failed envelope, or a failed `focus` action, other than `cancelled`; the message scrubbed to one line) and calls `System.ShowFailure(msg)`, a seam that tests replace with a recorder. The real one (`tty_unix.go`) opens `/dev/tty`, writes the message and a newline, puts the terminal in raw mode with `ioctl`s through `golang.org/x/sys/unix` (clearing `ICANON`, `ECHO`, `ISIG`; `VMIN` 1, `VTIME` 0; the set also drops what was typed ahead), reads one byte, and restores the settings; ctrl-c is that byte, as `ISIG` is off. Only the requests differ by system (`tty_linux.go`, `tty_darwin.go`): Linux reads with `TCGETS` and sets with `TCSETSF`, restoring with `TCSETS`; macOS reads with `TIOCGETA` and sets with `TIOCSETAF`, restoring with `TIOCSETA`. An error from any of it (no terminal, no key) is dropped: the envelope was delivered. Other systems don't show it (`tty_other.go` returns an error). `tty_unix_test.go` runs it in a child whose controlling terminal is a pseudo-terminal: raw mode set, what was typed ahead dropped, ctrl-c taken as the key, and the settings restored.
- **Testing.** `internal/pick/jump_test.go`: the order over a table crossing every attention, cache state, quiet time, and tie (and in reverse input order, so ties follow the input), each rule of `compareJump` alone, the spec's example lines verbatim, `cells`, the Cache column in a zone, hostile fields, the options (restart's unchanged) with the fake running the preview command on a key, the preview cases (a blocked, a stalled with `stall_reason`, and a self-waking session with pending counts; `pending` `null` and both counts `0`, each left out; a `liveness` row only for an unknown liveness; warm, cold, unknown, and `null` caches; `hit ratio` with `hit_ratio`, `misses`, and `last_miss_cause` each `null`, all three `null`, an empty `last_miss_cause`, one miss, and two causes joined; `context` with each of its three parts `null`; `cost` with `cost_usd` and the burn rate each `null`, and `metrics` `null`; a session without an ID, and an untitled one with an ID (`#3`, not `#3 #3`); no placement as a `tab title` of `—`; `extra` `{}` and `null` as a row of `—`; a title with a newline staying one row; a C1 character in `extra` written `\u009b`; the spec's example verbatim; the snapshot, each file's `quiet` and `cache` reading as its line's columns from the one `now`; the directory `sesshin-jump-` under `$XDG_RUNTIME_DIR`, mode `0700`, one file per candidate named by its key, gone before `focus` runs and after Enter, Esc, Enter with nothing matching, any other fzf status, and a failed `focus`; an `io` failure writing a file leaving no directory and starting no fzf; never made with no candidates or no terminal), `statusline.ContextText` and `Percent` against the statusline's own cases, each outcome row, the focus verified, unverified, and failed, the Errors order step by step, no candidates without a terminal, and `ShowFailure` against a recording seam: shown for a focus failure, `fzf-missing`, `no-terminal`, `fzf-failed` and a load error, not for a success (verified or not), a cancel, or nothing picked. The schema agreement is `jump-input` against `DecodeJumpInput` on the mutation corpus, and every envelope against `jump-output`. `internal/cli/jump_test.go` checks the command line and runs the real command against a stubbed `System`, including that the message is shown only after stdout holds the envelope, and not when stdout fails. `e2e/jump_test.go` runs the built `sesshin jump` in a pseudo-terminal against a real fzf: the preview pane shows the `attention:` row of the line under the cursor; Enter focuses (verified, with the fake `kitten`); Esc is `cancelled` and ends at once; a failing focus prints its message and waits, the envelope already on stdout, until a key (ctrl-c among them) ends it; and a missing fzf shows its message and waits, too.
- **jump for real,** a manual check in a scratch kitty: sessions at a dialog, finished, and working, with the overlay binding; the right one first, under the cursor, and Enter brings it to the front: in another tab, another OS window, and a second kitty instance, a split in the overlay's own tab, and the window the overlay covers. Closing the overlay must leave the picked window focused.

## The CLI

In `cmd/sesshin` and `internal/cli`: the envelope is printed as one line through `jsonio.MarshalLine`, which fills nil collections; usage errors carry `usage-details`; SIGPIPE is caught with `signal.Notify`, so a write to a closed stdout returns `EPIPE` and exits 3 (outcome unknown); a panic or fatal error ends by SIGABRT (exit 134, `debug.SetTraceback("crash")`) rather than Go's exit 2, which would read as a usage error; and `RLIMIT_CORE` is set to 0, as in `sesshin-hook`: the traceback on stderr is what a bug report needs, and systemd-coredump would otherwise keep a core of every panic. The CLI's tests validate every envelope they print against the schemas.

Each command is a table in `internal/cli`: its name, its summary, and one row per option (long name, the JSON Pointer of its field, its type, whether it is required), plus the function that checks the input with the operation's decoder and runs it (`operation`). The cobra command, its flags, and the input are generated from the table. A command may have positional arguments (`show`'s `<session>`): a table of required arguments, each with the JSON Pointer of the field it sets, in order. A token past the last is an unexpected argument (a usage error naming it); one missing is a usage error, unless `--input` is given, which together with an argument is one too. `-i, --input` is added to every command.

Parsing has four phases. Cobra parses the line; a bad boolean value (`--dry-run=maybe`) is a usage error there. Then the shape checks cobra lacks: a command name after `--`, `--input` together with an option that sets a field, and a missing required option (unless `--input` is given). Then the input is built from the options actually given, so defaults are the operation's. Last, `ops.CheckInput` checks it, or `ops.DecodeInput` checks the bytes of `--input`: the same decoder, so a bad value is the same `invalid-input` either way.

Conversion has four types. A boolean is a boolean flag. An integer is registered as a string flag, so every value reaches the operation's checks: a token matching `-?(0|[1-9][0-9]*)` becomes a JSON number, and anything else (`+1`, `01`, `1.0`, `abc`, the empty string) stays a string, which the operation rejects as the wrong type at that field. A string is a string flag, passed as it is. A list is a `StringArray` flag (not `StringSlice`, which would parse CSV quotes): each value is split at its commas, the lists of repeated options are joined in order, and `''` is the empty list; an empty item beside others (`a,,b`) stays an item and fails the operation's check at its own pointer. A positional argument is placed at its field as a string. A repeated single-value option's last value wins, and an option that takes a value always consumes the next token.

`--input` reads with a blocking `os.Open` and `io.ReadAll`, not fsys, so `<(...)` and named pipes work; `-` reads `Env.Stdin`, and stdin is read for nothing else. A missing or unreadable file, or a directory (it opens, and the read fails with `EISDIR`), is `io` with `path` as given and `code` the errno's name, built by `ops.IOError`, which install and prune reuse for their own OS errors. An error with no errno, or one with no name, is `internal`.

## Testing

### Where each kind of test runs

- **In-process:** validators, the JSON reader and writer, the effects table, rendering, the model-name rule, number formats, the settings proposal, liveness.
- **`e2e/`, against the built binaries:** everything the hooks contract promises (exit status, silence, panics), the lock between processes, install and uninstall against a temporary `settings.json`. The [hooks contract](hooks-spec.md#the-contract) requires it: an unrecovered panic's exit status can't be observed in-process.

### The e2e harness

`e2e/`, all in `_test.go` files, standard library and sesshin's own packages only (but `pty_test.go`: `creack/pty` and `vt10x`, for [the picker's test](#restart)), no goroutines but `TestConcurrentWriters`'s writers and `pty_test.go`'s reader of the pseudo-terminal.

- `TestMain` builds `sesshin` and `sesshin-hook` once with `go build`, from the module root, into a temporary directory removed afterwards. `build(dir, tags...)` takes build tags: `TestMain` builds a second set with `sesshintest` into a subdirectory, which `Harness.UseSesshintest` selects. The same directory holds two copies of the test binary, named `claude` and `kitten`.
- `New(t)` returns a `Harness` with its own temporary `HOME`. `XDG_*`, `CLAUDE_CONFIG_DIR`, `CLAUDE_PID`, `CLAUDECODE`, `CLAUDE_CODE_ENTRYPOINT`, `KITTY_*`, `TMUX`, `STY`, and every `SESSHIN_*` variable are removed (a test sets the ones it needs), and `PATH` starts with the directory of the fake `kitten`. `h.Loc` holds the config directory, state directory, and Claude settings path, from `loc.Resolve` against that environment. `h.Setenv` and `h.Unsetenv` change the environment of everything the harness starts, and resolve `h.Loc` again.
- `h.Hook(verb, payload)` runs `sesshin-hook <verb>` under a **fake `claude`**: the test binary, started as `claude`, which runs `sh -c '<sesshin-hook path> <verb>'` with the payload on stdin, as Claude Code does, and reports back. The path is single-quoted by the rule in [Registration](hooks-spec.md#registration). An empty verb runs `sesshin-hook` with none. `h.Run(command, payload)` runs any shell command the same way.
- The fake `claude` gives its child `CLAUDE_PID=<its own pid>`, `CLAUDECODE=1`, and `CLAUDE_CODE_ENTRYPOINT=cli`. It has no `CLAUDECODE` itself: a top-level Claude. `h.Nested = true` sets `CLAUDECODE=1` in its own environment: a session started by another session.
- A `Result` has `Exit` (`-1` when a signal ended the child or the 30-second limit did), `Signal` (the signal that ended the child; a crash under an `sh` that didn't exec it shows as exit `128+n` instead, so a crash test accepts either), `Stdout`, `Stderr`, `Duration` (the child's wall time, measured by the fake `claude`), and `ClaudePID`. `h.Sesshin(args...)` runs the `sesshin` CLI directly, with no fake `claude` and nothing on stdin.
- The **fake `kitten`** is first on `PATH`. It appends its argument vector, one JSON array per run, to a file the harness reads (`h.KittenCalls()`), so `spawn`'s tests can check what was launched. `h.Kitten(output)` makes it print `output` and exit 0; `h.KittenHangs(d)` makes it sleep `d` and exit 0; unconfigured it prints nothing and exits 1. The kitty backend's tests read the answer it prints as kitty's real `kitten @ ls` JSON (see below).
- The process shape is tested by running the test binary in `lookup` mode where `sesshin-hook` would be: it prints `proc.Find`'s result, its parent and grandparent, and its environment, on Linux and macOS.
- No test reads or writes the real `~/.claude/settings.json`: `HOME` is always the temporary directory.

### Test hooks

A panic must be injectable at a chosen point to test H1 and the statusline's per-step recovery. Hooks are compiled only into binaries built with a test tag (`-tags sesshintest`); the shipped binaries contain none, so no environment variable can make a real hook panic ([Configuration](design-spec.md#configuration): no environment variables).

- **Selection.** A `sesshintest` build reads `SESSHIN_TEST_PANIC=<point>` and panics the first time execution reaches that point. In the shipped build the injection call is an empty function the compiler removes, and the variable is never read; a contract test runs the shipped binary with it set and checks that the hook behaves normally. A `sesshintest` binary never ships, so this variable is not one of sesshin's settings.
- **Points,** one at each boundary where a panic could leave something half done:

  | Point | Where | Checked afterwards |
  |---|---|---|
  | `start` | `main`, right after its setup | H2: the recover is already in place |
  | `dispatch` | after stdin is decoded, before the verb runs | exit 0, nothing written |
  | `verb:<name>` | the entry of each verb | exit 0, silent; the statusline prints its fallback line |
  | `record:locked` | holding the session lock, before any write | the lock is released; the next hook records normally |
  | `record:written` | after `lifecycle.json` is renamed, before `sesshin.json` | `lifecycle.json` is usable; the next hook completes `sesshin.json` |
  | `record:state-locked` | holding the state lock | `state.json` is usable; no ID is issued twice |
  | `statusline:<n>` | each of the statusline's steps 1–6 | the step is skipped and logged; the line still prints (the fallback line, for step 5) |
  | `sync:returned` | `terminal-sync`, after `kitten` returns, before the lock | exit 0, nothing written |

  The point names are matched by a `switch`, not a table, so the `sesshintest` build passes the same guard tests as the shipped one: no work at package initialization.
- **A fatal error.** `SESSHIN_TEST_PANIC=fatal:<point>` ends the process with a real Go fatal error instead of a panic, a stack overflow (a small `debug.SetMaxStack`, then recursion), which no `recover` can catch. It tests [The hook binary](#the-hook-binary)'s promise: SIGABRT (exit 134), never Go's default exit 2. A test accepts either form of it, since `sh` reports a signal as exit 128+n (`Result.Signal`), and accepts on stderr only the shell's own report of the signal (`Aborted`, with ` (core dumped)` when a core handler took one): a `sh` that doesn't `exec` its last command (dash, Ubuntu's) prints it, and the hook's stderr is still `/dev/null`.

### Contract tests

`e2e/contract_test.go` proves [H1–H7](hooks-spec.md#the-contract) on the built binaries, one subtest per verb (all ten) in each case below. `TestHookContract` (`e2e/hook_test.go`) covers payload variety, an unknown verb, no verb, and `--help`. Each case here requires exit 0 and empty stdout and stderr (the statusline prints exactly its line), and that the next lifecycle hook then records normally: `lifecycle.json` written, `sesshin.json` with an ID. Cases that don't need an injection run the shipped binaries; the rest run the `sesshintest` ones (`Harness.UseSesshintest`).

- **No usable `HOME`:** unset, empty, `.`, and a relative path, with the hook's working directory a temp directory. Nothing is written there, nor logged.
- **An unusable file:** each of `lifecycle.json`, `sesshin.json`, `state.json`, `statusline.json`, and `hooks.properties`, as garbage, as `"schema": 99` (JSON, for `hooks.properties`; in another format, for the rest, which no verb replaces), and as a directory in its place. A table in the test gives, per verb and file, whether the verb logs it and whether it replaces it, as each verb's spec says; the test checks that table, and that a file a verb never reads is neither logged nor touched. The `state.json` cases start with no `sesshin.json`, since only a hook that issues an ID reads `state.json`.
- **A held lock,** with `hook_lock_wait_ms=100`: the session lock for every verb, and the state lock (on `sessions/`) with `sesshin.json` missing. A verb that takes the lock gives up after the wait and well inside the deadline, and logs `session lock` or `state lock`. A held session lock writes nothing; a held state lock leaves the event recorded and `sesshin.json` with a null `id` and its placement. The statusline and, for the state lock, `cwd-changed` and `terminal-sync` don't wait.
- **An injected panic** at every point of [Test hooks](#test-hooks) and every verb that reaches it, checking the table's last column. Each run is followed by the same verb with no injection, which must change something the injected run left undone, so a point that is never reached fails the test. After `record:state-locked`, a second session takes an ID different from the first's, and `state.json`'s `last_id` is the larger.
- **A fatal error** at `dispatch` (every verb) and `record:locked` (the verbs that take the session lock): SIGABRT or exit 134, never 2, with no output. Then the next hook records normally and doesn't wait: the death released the lock.
- **The shipped binary ignores `SESSHIN_TEST_PANIC`:** set to `verb:post-tool-use`, `dispatch`, `start`, `fatal:dispatch`, or `fatal:record:locked`, it records normally and logs nothing. The `sesshintest` build with the variable unset does too.

### Performance gate

Two tests, from [Hook cost](design-spec.md#hook-cost):

- **`TestHookCostGate`** (`e2e/perf_test.go`) is two gates on medians, each over a Go binary that does nothing (`testdata/donothing`, built by the same `go` into a temporary directory):
  - **Start-up:** `sesshin-hook post-tool-use` with empty stdin, which exits right after reading it, within **0.3ms**. This is where a stray linked package shows ([Hook cost](design-spec.md#hook-cost) has what each costs).
  - **Whole event:** `sesshin-hook post-tool-use` with a ~1KB payload, within **0.75ms**: start-up, plus reading `hooks.properties`, the session lock, reading and validating `lifecycle.json`, the write and rename, and checking `sesshin.json` (step 5). A first `post-tool-use` creates the session, so every timed run does that work, never an adoption; the test also checks that `event_seq` rose by at least n.

  The three are exec'd directly (no fake `claude`, no `sh`), in turn, n=500 each, after 50 warm-up runs of each; the time is measured by the test around `exec.Cmd.Run`. Every median and p99 is logged. The budgets leave room for the hook to grow and still catch what Hook cost guards against: they are set from these measurements.
- **`TestConcurrentWriters`** (`e2e/lifecycle_test.go`): 8 concurrent writers × 100 events to one session. The session starts with one prompt, so `event_seq` ends at exactly 801: the 800 events plus the prompt.

**Noise.** `go test ./...` runs packages in parallel, which can push a timing over the line, so the gate is opt-in: it runs only when `SESSHIN_PERF=1` is set, and never under `-short`. Run it with `SESSHIN_PERF=1 go test ./e2e -run TestHookCostGate -count=1 -v`, alone on an otherwise idle machine; [CI](#ci) leaves it out. A failed attempt is repeated once, so only a regression that shows in both fails it.

Measured on 2026-10-03, this machine (24 cores), n=500 interleaved, warm, `SESSHIN_PERF=1 go test ./e2e -run TestHookCostGate`:

| Run | Do-nothing median / p99 | Start-up median / p99 | Over | Whole event median / p99 | Over |
|---|---:|---:|---:|---:|---:|
| 1 | 0.887ms / 1.049ms | 1.035ms / 1.204ms | 0.148ms | 1.311ms / 1.528ms | 0.424ms |
| 2 | 0.888ms / 1.074ms | 1.031ms / 1.203ms | 0.143ms | 1.307ms / 1.534ms | 0.419ms |
| 3 | 0.891ms / 1.042ms | 1.046ms / 1.236ms | 0.154ms | 1.317ms / 1.518ms | 0.426ms |

Of the event's 0.42ms, about 0.14ms is starting a larger binary (3.9MB against 1.9MB; package initialization is about 0.07ms of it) with its signal, core-limit, and stderr set-up; the rest is the event's file work, about 20–40µs per file operation.

### CI

`.github/workflows/ci.yml` runs on every push to `main` and every pull request. Three jobs: **test**, on Linux (`ubuntu-latest`) and macOS (`macos-latest`), neither cancelling the other when it fails, checks `gofmt`, `go mod tidy -diff`, `go vet` with and without the `sesshintest` tag, and the build, fetches fzf with `scripts/fetch-fzf.sh` so the picker's end-to-end tests run, and runs `go test ./...`; **race**, on Linux, runs `go test -race` on every package but `e2e/`, whose tests run binaries built without it; **govulncheck**, on Linux, fails on a vulnerability sesshin's code calls. The [hook cost gate](#performance-gate) is not a step: its budgets are measured on one machine, and a shared runner's timings say nothing against them.

**Releases:** pushing a `vMAJOR.MINOR.PATCH` tag (no prerelease suffix) runs `.github/workflows/release.yml`: first `scripts/release-notes.sh`, which takes the tag's [CHANGELOG](../CHANGELOG.md) section, failing unless its heading is `## <version> — <YYYY-MM-DD>` (so a section still marked unreleased stops the release before anything is built), and makes its relative links absolute at the tag; then a check that `.claude-plugin/plugin.json`'s `version` is the tag's; then vet and test, then `scripts/release-build.sh`, which builds both binaries for Linux and macOS, amd64 and arm64, from the clean checkout (so Go stamps the tag as their version, and their build info matches for [`install`](operations.md#install)'s self-test), with `CGO_ENABLED=0` (macOS's `sysctl` is reached through `golang.org/x/sys/unix`'s libc trampolines, which need no cgo, and the linker signs the darwin/arm64 binaries ad hoc) and `-trimpath`, into one archive per system and architecture, `sesshin_<version>_<os>_<arch>.tar.gz` (`linux` or `darwin`), with `SHA256SUMS` over all four. Each archive holds the two binaries, `LICENSE`, `README.md`, `CHANGELOG.md`, `docs/`, `specs/`, `claude/` (the skill), and `scripts/opencode.sh`, so the README's links and the OpenCode script work from an unpacked archive. The release's notes are that CHANGELOG section.
